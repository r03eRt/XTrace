# Handoff — PR-026

- **Proveedor y modelo usados**: `provider: deepseek-official · model: deepseek-v4-flash`
- **Resumen**: Implementado el repositorio de la cola `jobs` del crawler sobre Postgres
  (Supabase local, migración PR-025): `jobs/types.py` (JobType 7 tipos DATA-002, JobStatus
  5 estados, entidad `Job` pydantic estricta) y `jobs/repo.py` (psycopg async) con
  `enqueue()` (con dedupe opcional por clave de payload), `claim_next()` con
  `FOR UPDATE SKIP LOCKED` y lease en la misma transacción, `complete()`, `fail()`
  (backoff de PR-023 vía `not_before`), `unavailable()` y `reset_stale_leases()`. Tests de
  integración contra Supabase local cubren toda la semántica de cola del contrato, con
  skip limpio si la BD no está disponible (patrón del spike).
- **Requisitos implementados**: FR-006 (cola `jobs` con `FOR UPDATE SKIP LOCKED`, sin
  Redis), FR-008 (reintentos con backoff exponencial + jitter, `max_attempts` configurable,
  estados terminales `done`/`failed`/`unavailable` sin reintentos infinitos) · ADR-0010
  (despacho, lease, backoff vía `not_before`) · contracts §3 (tipos/estados/retries/lease
  reset) · DATA-002 (7 tipos de job) · NFR-003 (tests deterministas, sin red para lo que no
  es BD).
- **Archivos modificados**:
  - `services/crawler/xtrace_crawler/jobs/types.py` — JobType/JobStatus/Job + coerce de
    enums (strict + valores de BD).
  - `services/crawler/xtrace_crawler/jobs/repo.py` — `JobsRepo` (psycopg async, dict_row,
    transacciones explícitas, DSN vía `resolve_dsn()` del spike, ADR-0011).
  - `services/crawler/xtrace_crawler/jobs/__init__.py` — **marcador del paquete `jobs`**
    (allowlist del contrato; documenta que `worker.py` llega en PR-027).
  - `services/crawler/tests/integration/test_jobs_repo.py` — 9 tests de integración.
  - `services/crawler/tests/integration/__init__.py` — **ANOTADO (fuera de allowed_paths,
    patrón aceptado Ola A)**: marcador de paquete necesario para que pytest recoja el
    módulo de integración; PR-028/PR-029/PR-027 reutilizan este directorio.
  - `docs/handoffs/PR-026.md` — este handoff.
- **Decisiones tomadas**:
  - **API async** (psycopg `AsyncConnection`): el worker de PR-027 es un bucle async y el
    spike ya usa el mismo driver/patrón (plan.md: `psycopg` como en el spike).
  - **`claim_next` = `UPDATE … WHERE id = (SELECT … FOR UPDATE SKIP LOCKED LIMIT 1)` con
    `RETURNING`** en UNA transacción: la fila elegida queda bloqueada y marcada
    `running`/`locked_by`/`locked_at` atómicamente (data-model.md, ADR-0010).
  - **`fail(terminal=False)`**: transitorio con intentos restantes → `pending` +
    `not_before = now() + next_attempt_delay(attempts)` (PR-023; jitter completo);
    transitorio agotado (`attempts >= max_attempts`) o `terminal=True` → `failed`
    definitivo. `unavailable()` es el terminal para 404/removed (spec edge cases). La
    distinción `failed` vs `unavailable` sigue data-model.md (404/removed → unavailable;
    bloqueo robots/ToS → failed definitivo vía `fail(terminal=True)`).
  - **Dedupe best-effort**: contracts §3 no exige índice único de payload; la migración
    PR-025 no lo incluye y no está en mi allowlist. `enqueue(dedupe_key=…)` persiste la
    clave en `payload.dedupe_key` y, en una transacción, devuelve el job activo existente
    (no terminal) sin insertar. Suficiente para operación normal; garantía estricta
    requeriría migración (tarea nueva).
  - **`delay_fn` inyectable** en `JobsRepo` (mismo patrón que `rng` en backoff.py PR-023):
    evita flakiness del test de backoff por jitter ~0 + latencia de conexión (NFR-003).
  - **`complete()` conserva `locked_by`/`locked_at`** como rastro de observabilidad
    (FR-014); `reset_stale_leases()` sí limpia el lease.
  - **Job no encontrado** en complete/fail/unavailable → `ValueError` explícito (error de
    uso del worker), no fallo silencioso.
  - **JSONB explícito** (`psycopg.types.json.Jsonb`): psycopg 3 no adapta `dict` a jsonb
    automáticamente con `%s`.
  - **`xtrace_spike.repo.resolve_dsn`** reutilizado (ADR-0011): una sola fuente de verdad
    del DSN (`SUPABASE_DB_URL` o Supabase local por defecto). Import con
    `# type: ignore[import-untyped]` porque el spike no declara `py.typed` (intocable).
- **Tests añadidos**: `tests/integration/test_jobs_repo.py` (9, contra Supabase local):
  claim único entre 8 workers concurrentes con 8 conexiones (FR-006); despacho FIFO por
  `created_at`; `not_before` futuro no elegible; transiciones enqueue→claim→complete
  (lease `locked_by`/`locked_at`); backoff programa `not_before` (attempts+1, pending,
  retraso ≈ now+delay); terminales sin reintentos (`fail(terminal=True)` → failed,
  `unavailable()` → unavailable, agotamiento de `max_attempts` → failed); lease reset de
  `running` vencidos → pending reclamable; lease vigente no se resetea; dedupe por clave
  de payload (no duplica activos, sí re-encola tras terminal). Cada test referencia su
  requisito (FR-006/FR-008/ADR-0010/contracts §3) en el docstring y limpia `jobs` al
  inicio (constitución §6). Skip limpio si la BD no está disponible o falta la migración
  PR-025 (comprobación en recolección, patrón del spike).
- **Comandos ejecutados** (todos con `UV_CACHE_DIR=/tmp/uv-cache-xtrace`, workdir
  `services/crawler`):
  - `uv sync` → venv creado, 38 paquetes instalados (psycopg 3.3.4, pydantic 2.13.4,
    mypy 1.20.2, ruff 0.16.3, pytest 8.4.2), éxito (exit 0).
  - `uv run ruff check .` → `All checks passed!`
  - `uv run ruff format --check .` → `23 files already formatted`
  - `uv run mypy xtrace_crawler` → `Success: no issues found in 13 source files`
  - `uv run pytest` → `93 passed` (84 unit + 9 integration) contra Supabase local
    (127.0.0.1:55322), sin BD simulada → `9 skipped` (skip limpio verificado).
  - Estabilidad: 15/15 corridas del módulo de integración sin fallos tras los fixes de
    robustez (antes: flakiness ~1/12 por jitter ~0 en el test de backoff).
- **Resultados**: gates verdes (ruff/mypy/pytest con BD local); semántica de cola
  verificada contra la BD real (claim único concurrente, backoff, terminales, lease
  reset, dedupe). Test-first cumplido: el test falló primero por `ModuleNotFoundError`
  (razón correcta) y quedó verde tras implementar.
- **Limitaciones**:
  - El dedupe por payload es best-effort (sin índice único; ver decisión). La migración
    PR-025 no está en mi allowlist.
  - `resolve_dsn` del spike se importa con `type: ignore[import-untyped]` (spike sin
    `py.typed`, intocable).
  - Sin pool de conexiones: una conexión por operación (suficiente para el volumen de la
    fase; revisable con métricas, ADR-0010).
  - `config.py` (secciones retries/DB pendientes según su docstring) no está en mi
    allowlist: la configuración de DSN/backoff vive en `repo.py`/`backoff.py`.
- **Riesgos**:
  - Flakiness de timing en tests de integración compartidos con otros worktrees sobre la
    misma BD local (locks de truncate/delete): mitigado con `DELETE` (menos bloqueante) y
    `delay_fn` inyectado; en CI aislado es determinista.
  - El claim concurrente depende del `FOR UPDATE SKIP LOCKED` real de Postgres: validado
    con 8 conexiones simultáneas; PR-027 debe respetar el mismo patrón (una conexión por
    claim).
- **Trabajo pendiente**: PR-027 (worker con handlers por `job_type`, lease reset
  periódico, aislamiento por fuente) consumirá esta API; PR-028 (repo sources/videos,
  stats) usará `JobType`/`JobStatus`; migración futura si se requiere dedupe estricto.
- **Instrucciones para el revisor**:
  - Verificar la semántica de `fail` (transitorio→pending+backoff; terminal/agotado→
    failed; unavailable separado) contra contracts §3 y data-model.md.
  - Verificar que `claim_next` marca el lease en la misma transacción (un solo UPDATE con
    subselect SKIP LOCKED).
  - Verificar la ausencia de lógica fuera del contrato (sin tocar spec/plan/migración;
    `delay_fn` y `dedupe_key` son puntos de extensión documentados).
  - Correr gates: `UV_CACHE_DIR=/tmp/uv-cache-xtrace uv run ruff check . && uv run ruff
    format --check . && uv run mypy xtrace_crawler && uv run pytest` (con Supabase local
    arriba para los 9 de integración).
