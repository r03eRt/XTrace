# Handoff TASK-006-T020

## Resumen

Se añadieron pruebas de integración Postgres para el fallback del refinamiento
temporal. Las pruebas usan el backend `PgVectorStore` y el proveedor fake
determinista, y se saltan limpiamente cuando Postgres no está disponible.

## Requisitos implementados

- FR-008 / SC-004: una fuente deshabilitada conserva el timestamp, ranking y
  provenance del índice base con estado `unavailable`.
- FR-009 / SC-006: el refinamiento no modifica filas ni el conteo de `frames`.
- FR-010: el `work_root` queda vacío tras fallback exitoso y tras fallo
  controlado del adapter.

## Archivos modificados

- `services/api/tests/integration/test_temporal_refinement_fallback.py`

## Decisiones

- Se sembraron fuentes, vídeos y frames con UUID propios por test.
- La limpieza elimina únicamente las filas creadas por la prueba; no se hace
  `TRUNCATE` global.
- La ruta de éxito usa `sources.enabled=false`; la ruta de fallo usa un
  adapter no registrado para ejercitar la degradación controlada.
- El snapshot de `frames` compara conteo y columnas observables antes/después.

## Limitaciones y riesgos

- La integración requiere el esquema Postgres/Supabase local; sin él queda
  marcada como `skip` por diseño.
- No se prueba una descarga real de assets: el alcance de T020 verifica la
  degradación y la inmutabilidad del índice.

## Trabajo pendiente

- Revisión independiente de la tarea.
- Integración de los resultados en la validación global de la feature.

## Instrucciones para el revisor

Comprobar que el fallback conserva el timestamp/provenance base, que el
snapshot de `frames` permanece idéntico, que ambos estados (`unavailable` y
`failed`) son honestos y que el cleanup del `work_root` se comprueba después de
cerrar `TestClient`.
