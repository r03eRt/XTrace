- **Decisiones tomadas**:
  1. **Esquema fiel a `data-model.md`**: `sources` (name UNIQUE, manifest jsonb, `enabled` default false = gate SEC-002); `jobs` (job_type CHECK con los 7 tipos de DATA-002, status CHECK pending/running/done/failed/unavailable, `payload` jsonb default `{}`, `attempts`/`max_attempts` 0/3, `not_before` default now, `locked_by`/`locked_at`/`error`); `videos` ampliado con 9 columnas NULL por defecto, FK `source_id → sources(id) ON DELETE SET NULL`, CHECK de status drop+add idempotente con `unavailable`/`removed`, índice único **parcial** `uq_videos_source_external WHERE source_id IS NOT NULL AND external_id IS NOT NULL` + índice de consulta `idx_videos_source_external`.
  2. **No destructiva y paridad con el spike**: `create ... if not exists` / `drop constraint|trigger + create` / `create index if not exists` (mismo patrón idempotente que `20260815000000_visual_search_spike.sql`); no se tocan tablas ni datos existentes; `uq_videos_local_ref` intacto (DATA-003). RLS: `enable row level security` + `revoke all ... from anon, authenticated` en `sources` y `jobs` (sin políticas → deny-by-default, acceso solo vía `service_role`). La función `set_updated_at` del spike **no se recrea**; solo se añaden los triggers `trg_sources_set_updated_at` y `trg_jobs_set_updated_at`.
  3. **Worktree**: existía un archivo de migración sin trackear (resto de un intento previo) con contenido conforme; se revisó contra el contrato/`data-model.md` y se reescribió con el mismo contenido final (modo 644) como entregable del PR.
  4. **Entorno sandbox**: la CLI de Supabase escribe telemetría en `~/.supabase` (denegado por el sandbox); se ejecutó todo con `SUPABASE_TELEMETRY_DISABLED=1`. No se usó `pnpm test:db` (el worktree no tiene `node_modules` y no se tocan dependencias JS): el contrato permite `supabase test db` directamente.
- **Tests añadidos**: `source_sdk_crawler_schema.test.sql` — 103 aserciones pgTAP: tablas `sources`/`jobs`; columnas (tipos y nulabilidad, incluidas las 9 nuevas de `videos`); defaults (`enabled=false`, `status=pending`, `attempts=0`, `max_attempts=3`, `payload={}`) funcionales; UNIQUE `name` y `local_ref`; índice único parcial (existencia + predicado + columnas); CHECK de `job_type` (7 tipos positivos + negativo), `jobs.status` (5 estados + negativo) y `videos.status` (unavailable/removed positivos + negativo); índices `idx_jobs_dispatch` (con columnas `(status, not_before)`), `idx_jobs_source`, `idx_jobs_type`, `idx_videos_source_external`, `idx_videos_status`; FKs con acción (SET NULL ×2, CASCADE); RLS activa + sin políticas + sin privilegios anon/authenticated + test negativo con `role anon` (42501); triggers y función `set_updated_at` reutilizada.
