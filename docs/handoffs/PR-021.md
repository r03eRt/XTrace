# Handoff — PR-021

- **Proveedor y modelo usados** (obligatorio para auditar coste — p. ej. `provider: deepseek-official · model: deepseek-v4-flash`):
  `provider: deepseek-official · model: deepseek-v4-flash`
- **Resumen**:
  `MockAdapter` determinista sin red en `xtrace_crawler/adapters/mock.py` (FR-003, SC-001):
  catálogo sintético generado por **seed** (external_ids estables `mock-vid-<índice>`,
  metadatos deterministas), paginación por **cursor** con `next_cursor`, `get_video()` →
  `VideoSource` sintético con URLs `http://mock.local/...`, `get_visual_assets()` →
  assets storyboard/thumbnail/preview (nunca vídeo, SC-006) y `check_availability()` con
  **estados configurables** (FR-012). **Inyección de fallos** (`MockFaults`) global o por
  external_id (transitorio / timeout / terminal-removed) que se propagan como **errores
  tipados** (`MockAdapterError` → `TransientError`/`TimeoutError`/`RemovedError`) para los
  tests de aislamiento (SC-008). + `tests/fixtures/` con **datos de catálogo**
  (`catalog.py`) y **harness de construcción de casos** (`harness.py`).
- **Requisitos implementados**:
  - FR-003 (`MockAdapter` + fixtures + harness: flujo completo sin red, determinista, CI).
  - SC-001 (flujo discover → get_video → get_visual_assets offline, determinista y estable
    entre ejecuciones; verificado también entre procesos con SHA-256 idéntico).
  - Soporte contractual: FR-001 (el mock satisface estructuralmente el protocolo
    `SourceAdapter`), FR-005/SC-006 (assets permitidos, degradación sin storyboard),
    FR-009 (manifest con `RateLimitSpec` declarado), FR-012 (estados de disponibilidad),
    FR-010/SC-008 (fallos contenidos en el adapter; un fallo no rompe discover/assets de
    otros vídeos), contracts §1 (firma idéntica al contrato).

- **Decisiones tomadas**:
  - **Catálogo precomputado en `__init__`** con un único `random.Random(seed)`: el RNG solo
    se consume en la construcción, en orden fijo por índice → el resultado es idéntico entre
    instancias, entre órdenes de llamada y entre procesos (SC-001 estricto).
  - **Errores tipados** en el propio `mock.py` (jerarquía `MockAdapterError`):
    `TransientError`, `TimeoutError` (subclase de `TransientError`: timeout es reintentable,
    FR-008) y `RemovedError` (terminal). El mensaje de `RemovedError` incluye "removed" para
    alinearse con `jobs/backoff.classify_error` (contracts §3: terminal, sin reintentos).
  - **`MockFaults` frozen**: fallos globales por método (`discover`/`get_video`/
    `get_visual_assets`), `by_external_id` (aplica a get_video y get_visual_assets del vídeo)
    y `availability` (estados por id + `availability_default`). `MockAdapter` **copia** los
    dicts al construirse (determinismo ante mutaciones posteriores).
  - **`check_availability` no lanza fallos**: los estados son configurables; vídeo fuera del
    catálogo → `removed` (no existe en la fuente).
  - **Degradación de assets** determinista: vídeos con `index % 5 == 0` no tienen storyboard
    (spec edge cases: "Vídeo sin storyboard → degradación según jerarquía, sin fallar").
  - **Acceso a valores esperados sin fallos**: `get_catalog_video()`/`catalog_snapshot()`
    (sync) permiten al harness montar expectativas aunque el adapter tenga fallos inyectados.
  - **Tests async con `@pytest.mark.anyio`** (backend asyncio): `anyio` es dependencia
    transitiva de `httpx` ya en el lockfile; no se añadió pytest-asyncio (pyproject.toml no
    está en allowed_paths y no hace falta).
  - `access_method="json"` en el manifest del mock (simula una fuente tipo API JSON
    sintética); `robots_reviewed`/`terms_reviewed=True` porque el contenido es 100 %
    sintético (SEC-004) — el gate SEC-002 real es de PR-028 (`registry.py`).
- **Tests añadidos**:
  `tests/unit/test_mock_adapter.py` — 40 tests: protocolo `SourceAdapter` y manifest
  compliant; flujo completo offline (SC-001); catálogo estable entre instancias, entre
  órdenes de llamada y con seeds distintos (ids estables, metadatos cambian); paginación
  completa (50 ids con limit=7, reanudación por cursor, página vacía al final, cursores y
  limits inválidos, catálogo vacío); assets (kinds/URLs `http://mock.local`, posiciones y
  timestamps de storyboard dentro de la duración, degradación sin storyboard, nunca
  `video`); fallos inyectados (globales por método, por external_id, jerarquía tipada,
  mensaje "removed", determinismo de fallos, kind inválido rechazado, aislamiento
  FR-010/SC-008); `check_availability` (default, por id, default global, fuera del
  catálogo); fixtures y harness (datos de catálogo válidos, `discover_all` recorre la
  paginación, catálogo esperado coherente, `with_faults`). Cada test referencia su
  requisito en el docstring (constitución §3).

- **Resultados**:
  Mock + fixtures + harness operativos: el flujo completo del crawler se puede testear sin
  red y de forma determinista (SC-001). Los fallos inyectados quedan contenidos en el
  adapter y se propagan tipados (base para los tests de aislamiento de PR-027/PR-030).
- **Limitaciones**:
  - `FaultKind` valida los valores en runtime en `MockFaults.__post_init__` (los dataclass
    no validan `Literal`); `# type: ignore[arg-type]` solo en el test del caso inválido.
  - `SAMPLE_VIDEOS`/`SAMPLE_ASSETS` son **ejemplos canónicos de forma** (literales), no
    instantáneas del catálogo generado con `FIXTURE_SEED`; para valores esperados del
    catálogo generado hay que usar `MockHarness.catalog()` (documentado en `catalog.py`).
  - Los tests async dependen del plugin de pytest de `anyio` (transitiva de httpx): si
    httpx dejara de depender de anyio habría que declarar pytest-asyncio (fuera del
    alcance; se anota para el orquestador).
- **Riesgos**:
  - PR-030 debe consumir `MockAdapter`/harness contra el **contrato** (no contra internos);
    `catalog_snapshot()`/`get_catalog_video()` existen justo para eso.
  - El mensaje "removed" de `MockAdapterRemovedError` es el acoplamiento intencional con
    `backoff.classify_error` (contracts §3); si el clasificador cambia, revisar los mensajes.
