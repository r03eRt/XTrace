# Handoff TASK-006-T007

## Resumen

Se añadieron los modelos compatibles de respuesta en Pydantic y Zod para el
resumen del refinamiento y la procedencia del timestamp. Los campos son
opcionales en el nivel de respuesta/resultado para que clientes antiguos sigan
funcionando, pero se validan completamente cuando aparecen.

## Requisitos implementados

- DATA-001: fuente, tipo de asset, posición y URL de evidencia tipados.
- UX-001..003: estados cerrados y procedencia diferenciada de `base_index` y
  `refined_asset`.
- SC-008: `match_timestamp_ms` se mantiene intacto y el payload legacy mínimo
  continúa siendo válido.

## Archivos modificados

- `services/api/xtrace_api/schemas.py`
- `src/lib/api/schemas.ts`

## Decisiones

- Pydantic usa `Literal`/Zod `enum` para impedir estados no reconocidos.
- Los contadores del resumen son enteros no negativos y se valida que
  `candidates_processed` no supere `candidates_requested`.
- `asset_kind` solo admite `thumbnail` o `storyboard`; `asset_url` queda nullable
  para resultados del índice base.

- `mypy` de schemas — PASS.
- Vitest de contrato — PASS (6 tests).

## Limitaciones y riesgos

- La integración del resumen con `POST /search` y la UI queda para T014/T017/T020;
  este task solo cambia las fronteras de tipos.
