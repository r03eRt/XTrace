# Handoff — PR-050

- **Proveedor y modelo usados** (obligatorio para auditar coste): `provider: deepseek-official · model: deepseek-v4-flash`
- **Resumen**: El crawler permite ahora elegir el proveedor de embeddings por
  env: `XTRACE_CRAWLER_EMBEDDINGS=fake|siglip` (default **`fake`**, igual que
  hoy). Con `siglip`, el contexto por defecto del CLI (`_default_context`,
  único punto donde se evalúa el switch) construye el pipeline con el
  **`SiglipLocalProvider` REAL** de `xtrace_spike.embeddings.siglip_local`
  (import dinámico, mismo patrón que el adapter xvideos; instanciado **sin
  argumentos**, paridad con el CLI del spike PR-005: `ViT-B-16-SigLIP`/`webli`,
  D=768, embeddings L2-normalizados) → `run-worker` indexa con embeddings
  reales en las validaciones del operador. La inyección de `deps.embeddings`
  para tests permanece intacta: los tests inyectan su propio `CliContext` y
  nunca cargan torch (el constructor de SigLIP es lazy, PR-005, y además el
  test del switch monkeypatchea el import/constructor).
- **Requisitos implementados**: FR-011 (el pipeline del crawler se alimenta con
  el proveedor SigLIP real del spike para validaciones reales — ADR-0011 ·
  contracts §6), NFR-001/003 (default `fake` sin torch en tests/CI), constitución
  §3 (trazabilidad PR-050 en docstrings, contracts y tests).
- **Archivos modificados** (allowed_paths del contrato, sin desviaciones):
  - `services/crawler/xtrace_crawler/config.py` — nuevo campo
    `embeddings: Literal["fake", "siglip"] = "fake"` (env
    `XTRACE_CRAWLER_EMBEDDINGS`; pydantic rechaza otros valores, fail-fast) +
    docstring del módulo.
  - `services/crawler/xtrace_crawler/cli.py` — nuevo helper
    `_embedding_provider_for(settings)` (solo `siglip` → import dinámico +
    `SiglipLocalProvider()` con `cast` al protocolo; `fake`/default → `None`);
    `_default_context` lo cablea a `CliContext.embeddings`. Docstring del
    módulo y del contexto actualizados.
  - `services/crawler/tests/unit/test_cli.py` — 4 tests nuevos (abajo) +
    `embeddings` param en `_base_context`.
  - `specs/002-source-sdk-crawler/contracts/README.md` — §6 documenta la env
    (valores, semántica, lazy torch, inyección para tests).
  - `docs/handoffs/PR-050.md` — este handoff.
- **Decisiones tomadas**: (1) El switch vive **solo** en `_default_context`
  (contexto por defecto real del CLI): los tests inyectan `CliContext` y nunca
  lo evalúan — sin torch en CI. (2) `siglip` → `None` de proveedor NO se
  inyecta para `fake`: `None` conserva el default del pipeline (PR-030),
  `FakeEmbeddingProvider(dimension=EMBEDDING_DIMENSION)` — comportamiento de
  hoy intacto. (3) Import dinámico (`importlib`) en vez de import estático:
  paridad con `_default_registry` (SC-007) y monkeypatcheable en tests sin
  tocar torch. (4) Sin cambios en `pipeline.py` ni en el spike (ADR-0011).
- **Tests añadidos** (trazados a FR-011 · contracts §6):
  - `test_settings_embeddings_default_and_validation` — default `fake` intacto;
    `siglip` aceptado; valor desconocido → `ValidationError`.
  - `test_default_context_embeddings_fake_by_default` — sin env, el contexto
    por defecto NO inyecta proveedor (`embeddings is None` → fake del pipeline).
  - `test_default_context_siglip_builds_real_provider` — con `siglip`, el
    contexto por defecto importa `xtrace_spike.embeddings.siglip_local` e
    instancia `SiglipLocalProvider()` sin argumentos (monkeypatch del import y
    del constructor; **sin cargar torch de verdad**).
  - `test_run_worker_uses_injected_embeddings_provider` — regresión de la
    inyección: un proveedor inyectado vía `CliContext.embeddings` llega al
    pipeline y se usa en INDEX_VIDEO (fake contador, sin torch).
- **Comandos ejecutados** (en `services/crawler/`, `UV_CACHE_DIR=/tmp/uv-cache-xtrace`):
  - `uv run ruff check .` → All checks passed
  - `uv run ruff format --check .` → 49 files already formatted
  - `uv run mypy xtrace_crawler` → Success: no issues found in 23 source files
  - `uv run pytest` → **362 passed** (358 baseline + 4 nuevos)
- **Resultados**: Gates verdes (ver arriba). Los tests nuevos fallaban antes de
  la implementación por la razón correcta (AttributeError: `Settings.embeddings`
  inexistente; import de `siglip_local` nunca ejecutado). Baseline 358 intacto;
  ningún test preexistente debilitado ni eliminado.
- **Limitaciones**: (1) Con `siglip` el `run-worker` real necesita el extra
  `siglip` instalado en el entorno del operador (torch/open_clip) para el
  primer `embed_images`; la selección en sí no lo exige (lazy). (2) La suite de
  integración comparte la Supabase local con el worktree PR-049: durante la
  ejecución simultánea aparecen fallos espurios de integración (truncates
  concurrentes); en aislamiento pasan y la suite completa da verde cuando el
  otro worktree no corre (mismo patrón que el baseline preexistente).
- **Riesgos**: Ninguno nuevo de seguridad: la env solo cambia el proveedor de
  embeddings (misma D=768 del esquema); sin secretos nuevos.
- **Trabajo pendiente**: Nada para esta tarea. Opcional del operador: usar
  `XTRACE_CRAWLER_EMBEDDINGS=siglip` en el backfill de validación real.
- **Instrucciones para el revisor**: Verificar (1) que el switch solo se evalúa
  en `_default_context` y que los tests inyectan su contexto (sin torch);
  (2) que el default sigue siendo `fake` (comportamiento de hoy intacto);
  (3) paridad de la instanciación con el spike (`resolve_embedding_provider`
  del CLI del spike: `SiglipLocalProvider()` sin args); (4) trazabilidad
  FR-011/ADR-0011/contracts §6 en docstrings y tests.
