# Handoff — PR-057

- **Proveedor y modelo usados**: `provider: deepseek-official · model: deepseek-v4-flash`
- **Resumen**: Página `/buscar` del skeleton Next.js (spec 003, D2): formulario de subida de
  imagen (drag&drop + file input, validación cliente de tipo JPEG/PNG/WebP y tamaño ≤ 10 MB con
  mensajes en español), estados `idle | loading | results | error` (UX-002), render de resultados
  (título o `local_ref`, fuente = dominio de `page_url`, score `0.000`, timestamp `mm:ss` o `—`,
  enlace "Ver original" `target=_blank` o ref local sin enlace) y cliente API con zod en
  `src/lib/api/` contra el contrato `POST /search` (contracts §1/§6) + env
  `NEXT_PUBLIC_XTRACE_API_URL` con default `http://127.0.0.1:8000`. Sin dependencias JS nuevas;
  home intacta. La ruta `/buscar` no lleva acento ni espacio: coincide con la convención del
  proyecto (sin cambios de ruta).
- **Requisitos implementados**: FR-009 (página única upload→resultados), FR-010 (enlace a la URL
  original cuando existe), FR-011 (UI de errores en español), FR-004 (zod del contrato como
  frontera estable), UX-001 (español), UX-002 (feedback de carga), UX-003 (score/timestamp/
  fuente/enlace), SEC-001 (solo local, sin auth), SEC-006 (config por env, `.env.example`),
  base de SC-005/SC-006 (validación cliente; el E2E WDIO es de PR-058). Nota: el encargo cita
  "FR-007/012/013", pero en tasks.md esos requisitos son de la API (PR-056/055); la tarea PR-057
  fija FR-009/010/011-UI + UX/SEC — se siguió tasks.md (contrato manda).
- **Archivos modificados**:
  - `src/app/buscar/page.tsx` (nuevo, server mínima + metadata)
  - `src/features/search/buscar-page.tsx` (nuevo, componente cliente)
  - `src/lib/api/schemas.ts` (nuevo, zod SearchResponse)
  - `src/lib/api/xtrace.ts` (nuevo, cliente fetch + helpers de formato)

  - `tests/unit/buscar-page.test.tsx` (nuevo, 17 tests)
- **Decisiones tomadas**:
  - UUIDs validados por **forma canónica** (regex 8-4-4-4-12 hex), no por
    `z.string().uuid()`: zod v4 exige versión/variante y rechazaría el ejemplo del contrato §1
    (UUIDs de versión 0) que PR-058 reutilizará como fixture E2E; los uuid4 reales de la API
    pasan igual. Documentado en `schemas.ts`.
  - `title`/`page_url` con `.nullish()` (extensión MAY: toleran ausencia y `null`).
  - Timeout de 60 s por AbortController interno (el snippet del contrato usa
    `AbortSignal.timeout`; se combinó manualmente para soportar también la señal de cancelación
    externa del componente). Cancelación → re-throw `AbortError`; la UI vuelve a `idle` sin
    estados colgados; timeout → `SearchApiError` "La búsqueda tardó demasiado…".
  - La UI usa estilos inline del skeleton (la home es la única página existente y usa el mismo
    patrón; **no hay Tailwind/shadcn** en este skeleton pese a lo indicado en el encargo — plan.md
    §Technical Context lo confirma). Selectores estables por `data-testid` para el E2E de PR-058.
  - No se toca `src/app/page.tsx` (el contrato no pide enlace en la home).
- **Tests añadidos**: `tests/unit/buscar-page.test.tsx` — estados idle/loading/results/error;
  validación cliente de tipo y tamaño (sin llamar a la API); resultados desde fixture del
  contrato §1 (título, fuente, score, timestamp, enlace `_blank`); resultado local sin URL sin
  enlace; `results: []` → estado vacío sin error; error de red y 5xx estructurado en español;
  cancelación al cambiar de fichero; cliente multipart (`image`, `top_k`, `min_score`) contra la
  URL por env; timeout de 60 s; zod acepta el contrato, tolera la extensión MAY y rechaza
  desviaciones.
- **Comandos ejecutados**: `pnpm install --ignore-scripts` (worktree sin node_modules);

  `pnpm lint` ✓ · `pnpm typecheck` ✓ · `pnpm test` ✓ (20/20) · `pnpm build` ✓ (ruta `/buscar`
  estática, con `.env.local` temporal no commiteado, vars Supabase preexistentes); smoke manual

- **Resultados**: gates JS verdes con salida real; 17 tests nuevos pasan; build incluye la ruta
  `/buscar`; home y sus tests intactos (`tests/unit/home.test.tsx` verde).
- **Limitaciones**: validación de tipo MIME por `file.type` declarado en cliente (la validación
  definitiva por firma es servidor, PR-055 — SEC-002); el flujo completo contra la API real se
  valida en PR-058 (SC-002 puerta del operador); timeout por AbortController manual en lugar del
  snippet literal `AbortSignal.timeout` del contrato (misma semántica: 60 s, abort).
- **Riesgos**: PR-058 debe usar los `data-testid` aquí fijados (`search-*`) y el fixture del
  contrato (ahora aceptado por zod gracias a la decisión de UUIDs); si el fixture E2E usara
  `z.string().uuid()` estricto fallaría el render — ya evitado.
