- **Requisitos implementados**: FR-003 (base de CI sin red, paquete importable) · ADR-0011 (dependencia editable al spike) · plan §Project Structure y §CI strategy · NFR-001 (toolchain local ~0 €, mismo patrón que el spike) · SEC-003 (config por env, sin secretos en el repo).
- **Archivos modificados** (solo `allowed_paths`; nada más):
  - Creados: `services/crawler/pyproject.toml`, `services/crawler/xtrace_crawler/__init__.py`, `services/crawler/xtrace_crawler/config.py`, `services/crawler/xtrace_crawler/cli.py`, `services/crawler/tests/__init__.py`, `services/crawler/tests/unit/__init__.py`, `services/crawler/tests/unit/test_smoke.py`, `services/crawler/Dockerfile`, `services/crawler/README.md`, `services/crawler/.gitignore`, `services/crawler/.python-version`, `services/crawler/uv.lock` (generado por `uv sync`), `.github/workflows/python-crawler-quality.yml`, `docs/handoffs/PR-019.md`.
- **Decisiones tomadas**:
  1. **Rama**: `feature/002-source-sdk-crawler/PR-019-…` es imposible en git (un ref no puede ser a la vez rama hoja y namespace de ramas). Usé el esquema real de la fase 1 (19 ramas precedentes): `feature/002-source-sdk-crawler-PR-019-bootstrap-service-crawler-ci`. El orquestador debe actualizar tasks.md/contrato si quiere normalizar el esquema (p. ej. documentar `feature/NNN-feature-PR-0NN-slug`).
  2. **Versiones**: mismas que el spike (`typer>=0.15,<1`, `mypy>=1.14,<2`, `pytest>=8.3,<9`, `ruff>=0.9,<1`); añadida `pydantic-settings>=2.6,<3` (resuelta 2.15.0). Config ruff/mypy/pytest idéntica al spike (strict, line-length 100, select E/F/I/UP/B).
  3. **Config**: prefijo `XTRACE_CRAWLER_` (pydantic-settings); campos base `supabase_url` y `supabase_service_role_key` (contrato PR-019, SEC-003) + `log_level` y `request_timeout_seconds`. Las secciones rate/retries/DB llegan en PR-022/PR-026.
  4. **CLI vacía**: Typer con `no_args_is_help=True` + **callback mínimo sin lógica** — Typer `CliRunner` no puede invocar una instancia Typer sin comandos ni callback (`RuntimeError: Could not get a command…`, verificado en ejecución); el callback la convierte en grupo invocable. Sigue siendo CLI vacía (0 comandos, 0 lógica de dominio).
  5. **CI aditivo**: nuevo workflow `python-crawler-quality.yml` espejo del spike con `working-directory: services/crawler`; dispara también ante cambios en `services/search-spike/**` (dependencia editable, ADR-0011). No toca `quality.yml` ni `python-quality.yml`.
  6. **Dockerfile**: la dep editable vive en `../search-spike`, así que el build context es la **raíz del repo** (`docker build -f services/crawler/Dockerfile -t xtrace-crawler .`); usa imagen `ghcr.io/astral-sh/uv:python3.11-bookworm-slim` y `uv sync --frozen --no-dev` para respetar `[tool.uv.sources]` (pip no entiende `[tool.uv.sources]`).
  7. **`.uv-cache/`** añadido al `.gitignore` del servicio (el sandbox impide escribir en `~/.cache/uv`; las ejecuciones usaron `UV_CACHE_DIR` local al workspace).
- **Tests añadidos**: `tests/unit/test_smoke.py` — (1) paquete importable + versión; (2) `xtrace_spike` resoluble desde el crawler (ADR-0011); (3) `--help` de la CLI con Typer `CliRunner` (exit 0, muestra `Usage` y `xtrace-crawler`). Todos marcan el requisito que validan (constitución §3).
