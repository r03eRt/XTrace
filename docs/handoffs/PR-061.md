# Handoff — PR-061

- **Proveedor y modelo usados**: `provider: deepseek-official · model: deepseek-v4-flash`
- **Resumen**: Fix del bug reportado por el operador (2026-08-17): en `/buscar` no se podía
  arrastrar ni seleccionar una imagen en Safari/macOS. El `<input type="file">` estaba FUERA
  del `<label>` (hermano), oculto con `position:absolute + 1px + opacity:0 + overflow:hidden` —
  patrón que en Safari no abre el selector al hacer clic en el label. Se mueve el input DENTRO
  del label `search-dropzone` (primer hijo) y se sustituye el ocultado por el patrón `sr-only`
  clásico con `clip-path: inset(50%)` (sin `opacity:0`), que funciona en Safari/Chrome/Firefox
  y conserva el foco de teclado (accesibilidad).
- **Requisitos implementados**: FR-009 (subir imagen en `/buscar`) restaurado en el navegador
  del operador; UX-001/002/003 y SEC-005 intactos (la media de consulta nunca se persiste ni se
  loguea; la validación definitiva sigue en servidor). Fix post-fase de la spec 003 (ya
  `IMPLEMENTING`/cerrada).
- **Archivos modificados**:
  - `src/features/search/buscar-page.tsx` (único cambio de código: input `search-file-input`
    movido dentro del label como primer hijo; estilo oculto → `sr-only` clásico:
    `position:absolute; width:1px; height:1px; margin:-1px; padding:0; border:0;
    clip-path:inset(50%); overflow:hidden; white-space:nowrap`; se conservan `id`,

  - `docs/handoffs/PR-061.md` (este handoff)
  - No tocados: `tests/e2e/specs/search.smoke.e2e.ts` y `tests/unit/buscar-page.test.tsx`
    (ningún selector se rompió: `setValue` de WDIO y `user.upload` de Testing Library siguen
    funcionando sobre el input sr-only; `htmlFor` del label se mantiene — inofensivo y explícito)
- **Decisiones tomadas**:
  - Input dentro del label (patrón robusto recomendado por el operador) en lugar de
    `label[htmlFor] -> input hermano`: el clic en el label activa el input en todos los
    navegadores, incluido Safari/macOS.
  - `sr-only` sin `opacity:0` ni `display:none`: el input permanece enfocable por teclado
    (Tab + Enter abre el selector), requisito de accesibilidad no cubierto por el patrón
    anterior.
  - Se conserva `htmlFor="search-file-input"` aunque el input ya esté dentro: redundante pero
    inofensivo, y evita tocar más de lo necesario.
  - Sin tests nuevos: la regresión se cubre con los tests existentes (unitarios por `testid`
    sobre el input, E2E por `setValue`) — ambos verdes sin cambios.
- **Tests añadidos**: ninguno (ver decisión); los 17 unitarios de `buscar-page.test.tsx` y los
  4 E2E de `search.smoke.e2e.ts` validan el comportamiento completo (upload → resultados).
