# Handoff TASK-006-T026

## Resumen

Se amplió el stub HTTP real usado por WebdriverIO para seleccionar respuestas de
refinamiento mediante el nombre del fichero de consulta. La smoke suite conserva
el flujo existente y añade cobertura de timestamp refinado y de degradación a la
evidencia del índice base cuando el refinamiento está limitado o no disponible.

## Requisitos implementados

- UX-001: un resultado refinado muestra `Timestamp refinado (aproximado)`, el
  timestamp refinado y el enlace original.
- UX-002: un refinamiento limitado muestra el feedback de disponibilidad y
  conserva el resultado base.
- UX-003: un refinamiento no disponible no se presenta como ausencia del vídeo;
  se mantiene timestamp, badge del índice base y enlace.
- SC-004/SC-008: fixtures `limited` y `unavailable` devuelven HTTP 200 con
  resultados válidos y sin `search-error`; el caso `bad.png` mantiene el error
  HTTP 415 existente.
- El stub sigue siendo un servidor HTTP real sin interceptores de navegador y
  no contacta fuentes externas.

## Limitaciones y riesgos

- Los tres ficheros PNG de escenario son copias de la imagen sintética 1×1 y solo
  sirven para enrutar el fixture por nombre; el stub no evalúa contenido visual.
- La captura automática en caso de fallo permanece en el hook `afterTest` de
  `wdio.conf.ts`, que no forma parte de los `allowed_paths` de esta tarea.

## Revisión solicitada

Comprobar que el selector de fixture no permite rutas arbitrarias, que los
fixtures respetan el schema REST y que los escenarios distinguen refinado,
limitación/no disponibilidad y error HTTP sin usar Playwright/Cypress.
