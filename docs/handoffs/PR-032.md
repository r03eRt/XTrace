# Handoff — PR-032

- **Proveedor y modelo usados** (obligatorio para auditar coste — p. ej. `provider: deepseek-official · model: deepseek-v4-flash`): `provider: deepseek-official · model: deepseek-v4-flash`
- **Resumen**: Implementada la **CLI operativa completa** de `xtrace-crawler` (Typer, contracts §5): `sources [--json]`, `backfill --source <name> [--limit N] [--incremental]`, `run-worker [--concurrency N] [--once]`, `stats [--json]` y `check-availability --source <name> [--limit N]`. Salida de datos **SIEMPRE JSON estable por stdout** (`sort_keys`, UTF-8); logs y errores de usuario a **stderr** con **exit code != 0** (1 = dominio, 2 = uso). `backfill` valida la fuente (registry + BD + gate SEC-002) y encola el job `DISCOVER` inicial con el **payload del contrato de PR-030** (`{"source", "cursor": None, "limit", "mode"}`); `run-worker` cablea el `JobWorker` (PR-027) con los **handlers del pipeline** (PR-030) y el registry (cada job resuelve su adapter con SEC-002 y el `enabled` de `sources`, snapshot al arrancar); `check-availability` encola `CHECK_AVAILABILITY` por vídeo web de la fuente (FR-013). `config.py` gana `worker_concurrency`, `job_lease_timeout_seconds`, `backfill_default_limit` y `check_availability_default_limit` (override por env `XTRACE_CRAWLER_*`) **sin romper la base PR-019/022**. DI por `ctx.obj` (`CliContext`): tests con `CliRunner` + fakes, sin red y sin BD (NFR-003).
- **Requisitos implementados**: FR-006 (encolado vía `JobsRepo` con `dedupe_key` y despacho `--once`/bucle del worker), FR-007 (`backfill` BACKFILL/INCREMENTAL con cursor inicial y límite), FR-013 (`check-availability` por vídeo), FR-014 (`stats` con jobs por estado/fuente —clave `None` normalizada a `"null"`—, vídeos por estado y errores recientes con causa ISO), SEC-002 (gate en `backfill`/`check-availability`/resolución del worker con mensaje legible), NFR-004 (límites por fuente respetados: el pipeline ya rate-limitea cada llamada; el CLI no añade llamadas fuera del contrato), NFR-003 (tests deterministas sin red/BD), contracts §5 (JSON estable, errores con exit != 0, `--limit` con `min=1` → exit 2), D2/D4/D5 (misma BD local; overrides por env en config), SC-007 (el core no importa estáticamente el adapter xvideos — test AST de PR-031 sigue verde).

- **Decisiones tomadas**:
  - **DI por `ctx.obj`** (`CliContext`): el callback construye el contexto por defecto (repos reales + registry mock/xvideos) si `ctx.obj is None`; los tests inyectan fakes con `CliRunner.invoke(..., obj=...)` (verificado: typer 0.27 reenvía `obj` al Context y stderr se captura aparte). Sin singletons globales ni ficheros fuera de allowed_paths.
  - **Salida**: datos → stdout JSON estable; `sources`/`stats` tienen vista humana por defecto y `--json` estable (flag del contrato); `backfill`/`check-availability`/`run-worker --once` emiten JSON siempre (`{job_id, source, mode}`, `{source, limit, enqueued, job_ids}`, `{"processed": N}`; `run-worker` sin `--once` imprime `{"stopped": true}` al parar con Ctrl+C/SIGTERM). Errores de usuario → stderr `Error: …` + exit 1; límites inválidos → error de uso de typer (exit 2).
  - **Validación de fuente** (`backfill`/`check-availability`): 1) registry (`fuente desconocida` con adapters registrados), 2) BD (`no registrada en la BD (tabla sources)` — la habilitación humana es `sources.enabled`, SEC-002; no hay seed en la migración), 3) `registry.get_enabled` con el `enabled` de BD (gate SEC-002 con razones legibles; el mock queda exento, FR-003).
  - **`run-worker` real**: `_build_worker` precarga el snapshot `sources.enabled` por adapter (el resolver del pipeline es síncrono) y construye `CrawlerPipeline` (PR-030) + `JobWorker` con `concurrency` y `lease_timeout_seconds` de config; `store`/`embeddings`/`worker` inyectables en `CliContext` (p. ej. SigLIP local, nota PR-030 "trabajo pendiente").
  - **SC-007 (test AST de PR-031)**: el registro de `XvideosAdapter` (composición raíz) se hace con **import dinámico** (`importlib.import_module("xtrace_crawler.adapters.xvideos")` + `Any`) para no violar `test_core_no_importa_el_adapter_xvideos` (ningún módulo del core importa estáticamente el adapter). Documentado en `_default_registry`.
  - **Listado de vídeos de una fuente**: `repo.py` no expone listado y no está en allowed_paths → `CliContext.list_source_videos` es un callable inyectable; el default ejecuta SQL de solo lectura sobre la conexión del repo (SEC-003: credenciales de servidor).
  - **Logging**: `_setup_logging` solo configura si la raíz no tiene handlers (en pytest no se toca la captura; en producción StreamHandler a stderr). Sin `force=True` para no interferir con pytest.
- **Tests añadidos** (23, en `tests/unit/test_cli.py`, todos sin red y sin BD — NFR-003):
  - `sources`: humano (manifest + enabled), `--json` estable entre invocaciones (claves canónicas), `[]` sin fuentes.
  - `backfill`: encola DISCOVER con el payload del contrato (`cursor=None`, `limit`, `mode`, `dedupe_key`); `--incremental` y límite por defecto desde config; errores: fuente desconocida (exit 1), no registrada en BD (exit 1), no habilitada con razones SEC-002 (exit 1), `--limit 0`/`abc` (exit 2).
  - `run-worker`: `--once` con worker inyectado despacha jobs fake (handler invocado, job `done`, `{"processed": 1}`); cola vacía → `{"processed": 0}`; **sin inyección** cablea pipeline+registry y procesa 1 DISCOVER → 5 vídeos + 5 FETCH_METADATA + 5 INDEX_VIDEO (total 11, determinista; assets http degradan → transitorio, sin red); `--concurrency 0` → exit 2.
  - `stats`: humano y JSON coherentes (FR-014); clave de fuente `None` → `"null"`; ISO en errores; JSON idéntico entre invocaciones; conteos vacíos.
  - `check-availability`: encola por vídeo con payload/dedupe correctos; `--limit` acota la consulta; sin vídeos → `enqueued: 0`; fuente desconocida/no habilitada → exit 1; `--limit 0` → exit 2.
  - `config.py`: defaults (4/300/50/100), overrides por env, `worker_concurrency=0` rechazado (ValidationError).

- **Limitaciones**:
  - `backfill`/`check-availability` exigen la fila en `sources` (BD): no hay seed ni comando de registro (fuera de alcance); el operador crea la fila (p. ej. SQL) y habilita con `sources.enabled` tras la revisión legal (SEC-002). El pipeline (`sync_source`) la crea al procesar un DISCOVER ya encolado.
  - El snapshot de `enabled` del worker se toma al arrancar: cambiar `sources.enabled` requiere reiniciar `run-worker` (el resolver del pipeline es síncrono).
  - `run-worker` sin `--once` (bucle con Ctrl+C) no está cubierto por tests unitarios (bloquearía el runner); el camino `--once` y la construcción del worker sí.
  - Un job de fuente no habilitada en el worker falla como transitorio (retry acotado → `failed`) porque `AdapterNotEnabledError` no es terminal en `jobs/backoff` (fuera de allowed_paths).
  - `sources`/`stats` sin `--json` usan vista humana (el contrato exige JSON estable solo con el flag para estos dos; el resto emite JSON siempre).
- **Riesgos**:
  - El import dinámico de xvideos (`Any`) pierde el tipado estático de la instancia en la composición raíz; el contrato se mantiene vía el protocolo `SourceAdapter` del registry (gate en runtime). Si un futuro PR añade un `default_registry()` en `adapters/`, el CLI debería delegar ahí (y el test AST seguiría verde).
  - `list_source_videos` duplica SQL en el CLI (fuera de `repo.py` por allowed_paths): si un PR futuro añade `list_web_videos` al repo, conviene migrar el default del contexto.
- **Trabajo pendiente**: PR-033 (validación operativa con xvideos real tras revisión legal humana: registrar fila `sources`, `enabled=true`, `backfill` acotado, evidencias). Quickstart de la fase (`specs/002-source-sdk-crawler/quickstart.md`, PR-033) deberá documentar los comandos con ejemplos reales.
