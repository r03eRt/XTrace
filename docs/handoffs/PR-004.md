## Decisiones tomadas

1. **64 bits vía `imagehash.phash(hash_size=8)`**: librería ya declarada en `pyproject.toml`
   por el orquestador (plan §Technical Context: `imagehash`). `phash()` normaliza internamente
   (gris, 32×32, DCT), así que el modo/tamaño de entrada no cambia el contrato.
2. **Representación como `int` sin signo**: `np.packbits` del array booleano 8×8 → 8 bytes →
   `int.from_bytes(..., "big")`. Es exactamente 64 bits (verificado: `bit_length()==64`) y
   determinista. No se usa `ImageHash.__hash__` (int de 8 bits truncado, no fiable).
3. **Hamming con `int.bit_count()`**: `(a ^ b).bit_count()`, O(1) y sin dependencias.
4. **API mínima**: sin umbral de similitud en este módulo — el umbral configurable es del
   dedupe (FR-003, PR-009), que consumirá `hamming_distance`. Sin parámetro `hash_size`
   expuesto para no romper el invariante de 64 bits.
5. **Test-first**: los tests se escribieron antes del módulo y fallaron por la razón correcta
   (`ModuleNotFoundError: xtrace_spike.hashing`).

## Limitaciones

- pHash cubre solo **near-exact** (FR-004/ADR-0005): crop, watermark, color y encuadre
  corresponden a la señal semántica de embeddings (PR-005/PR-013), fuera de esta tarea.
- No se fijan *golden values* absolutos en los tests: se verifican propiedades relativas
  (determinismo, estabilidad, coherencia), robustas ante variaciones de plataforma.
- `imagehash.phash` usa `scipy.fftpack` internamente; scipy entra como dependencia
  transitiva ya resuelta por `uv.lock` (sin cambios en `pyproject.toml`).
- El rango de entrada razonable es de unas pocas imágenes pequeñas; para el pipeline de
  indexación el coste real vendrá dominado por la extracción de frames (PR-008).

## Riesgos

- Umbrales de test (10/12 bits) calibrados sobre imágenes sintéticas estructuradas; con
  vídeo real (compresión fuerte, ruido) la distancia near-exact puede crecer: PR-009 debe
  validar el umbral configurable de dedupe con el dataset real.
- Determinismo ligado a las versiones fijadas en `uv.lock` (numpy, pillow, imagehash):
  cualquier bump de dependencias exige re-validar los tests.
- Compatibilidad de consumo: PR-005, PR-009 y PR-012 importarán `compute_phash`/
  `hamming_distance`; el contrato queda estabilizado vía `hashing/__init__.py`.
