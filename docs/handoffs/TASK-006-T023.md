# Handoff TASK-006-T023

## Resumen

Se implementó la telemetría server-side del refinamiento temporal. El writer
valida estados y contadores antes de tocar la base de datos, hace upsert por
`search_id`, persiste únicamente métricas agregadas y evidencia pública
sanitizada, y trata cualquier fallo de persistencia como best-effort. `POST
/search` crea primero el registro padre en `searches` y después registra el
resumen del refinamiento sin alterar la respuesta si la telemetría falla.

## Requisitos implementados

- Una fila por `search_id` mediante `ON CONFLICT(search_id)` y `finished_at`.
- Estados acotados (`completed`, `disabled`, `unavailable`, `limited`, `failed`)
  y contadores no negativos con relaciones de suma validadas.
- Evidencia limitada a `thumbnail`/`storyboard`, URL HTTP(S) pública sin
  credenciales, query ni fragmento, hash SHA-256 calculado en servidor y
  deduplicación estable.
- No se reciben ni persisten bytes de consulta, vídeo o assets.
- Integración best-effort posterior a `record_search`, usando conexión
  server-side, sin cambiar ranking, `frames` ni el primer pase.

## Limitaciones y riesgos

- La prueba positiva server-side de RLS/cascade depende de que Supabase local
  tenga aplicada la migración; sin esa base el test de integración se marca
  `skip` por diseño.
- La evidencia se construye desde el provenance seleccionado por el evaluador;
  los assets descartados permanecen representados por contadores y motivo, no
  por bytes ni payloads remotos.
