- **Decisiones tomadas**:
  - **Handlers concretos en pipeline.py** (no los factories base de PR-027): el rate
    limit (FR-009) debe envolver **cada llamada individual** al adapter
    (discover/get_video/get_visual_assets/check_availability), no el job entero; los
    factories base de PR-027 no lo permiten. Se documenta en el docstring.
  - **Payloads de jobs** (contrato interno documentado para PR-032): `DISCOVER =
    {"source", "cursor"|null, "limit", "mode": "backfill"|"incremental"}` (default
    backfill, contracts §5); `FETCH_METADATA`/`INDEX_VIDEO`/`CHECK_AVAILABILITY =
    {"source", "external_id"}`. Dedupe de jobs activos vía `dedupe_key`
    (`fetch_metadata:<src>:<id>`, `index_video:<video_id>`, `discover:<src>:<cursor>:<mode>`).
  - **DISCOVER hace `get_video` por ID** (rate-limiteado): `CrawlerRepo.upsert_web_video`
    exige un `VideoSource` completo y la fila debe existir antes de encolar con
    `video_id` (FK). INCREMENTAL omite IDs ya existentes (SC-003) y solo encola
    FETCH_METADATA para IDs nuevos.
  - **Índice = frame por asset**: los assets storyboard/thumbnail con `timestamp_ms`/
    `position` del mock SON frames; un sprite sin esos campos se indexa como frame único
    salvo `storyboard_grid` inyectado (recorte de tiles con timestamp aproximado, PR-029).
    Previews: FFmpeg vía `PreviewFrameExtractor` con `out_dir=path.parent` (los JPEGs
    viven en el temporal del asset y se borran con él, FR-015).
  - **Fallo de adapter → worker** (retry/terminal único, PR-027); **fallo de procesado de
    asset** (descarga/preview/crop) → **degradación por asset** con warning (spec edge
    case: la jerarquía nunca tumba el vídeo); 0 frames de todos los assets → error
    transitorio (retry con backoff).
  - **Spike reutilizado**: `compute_phash`, `frame_id_for` (ids de frame estables por
    (video_id, frame_seq), paridad de idempotencia), `PgVectorStore` (default del store),
    `FakeEmbeddingProvider(dimension=768)` como default de embeddings (tests/CI); el real
    (SigLIP) se inyecta para ejecución local. Los módulos del spike se importan con
    `# type: ignore[import-untyped]` (patrón de jobs/repo.py).
  - **Cliente HTTP de assets**: inyectable (`client`); default seguro derivado de las URLs
    de los assets con **solo https** (SEC-001; los adapters http en dev inyectan su
    cliente con `allow_http=True` + transporte, como el mock en tests).
  - **`unavailable()` no incrementa `attempts`** (jobs/repo.py PR-026): los asertos de
    terminales usan `attempts == 0`, no 1.

- **Limitaciones**:
  - El vídeo que agota reintentos queda en `discovered`/`indexing` (el pipeline no marca
    vídeo `failed`: repo.py no está en allowed_paths y la política de retries es del
    worker/job); un CHECK_AVAILABILITY o re-encolado posterior reconcilia.
  - `videos.frame_count` no se actualiza (el repo no expone setter; fuera de allowed_paths).
  - Sprites storyboard sin `position`/`timestamp_ms` (xvideos) se indexan como frame
    único salvo inyectar `storyboard_grid` (el adapter no expone el grid; xvideos sigue
    deshabilitado por SEC-002).
  - La colisión de `frame_seq` entre el tile 0 del storyboard y el primer frame del
    preview (ambos t=0) hace que el upsert reemplace (no duplique): comportamiento
    idempotente del spike, documentado en los tests.
  - Previews sin FFmpeg degradan (skip del asset) en CI; los conteos de los tests se
    ajustan vía `ffmpeg_available()`.
- **Riesgos**:
  - Flakiness de timing en integración compartida con otros worktrees: mitigado con
    `truncate ... cascade` por test, `delay_fn=0` inyectado para agotar intentos en una
    pasada y asertos sobre estados finales (no sobre orden de despacho).
  - El `Settings()` fresco por pipeline lee env en construcción: los tests usan
    `monkeypatch` antes de construir (overrides D5) — si se añadiera `get_settings()`
    cacheado el comportamiento cambiaría (documentado en pipeline).
  - Fallos de BD no aislados (fail-fast del worker, PR-027): fuera del alcance de SC-008.
