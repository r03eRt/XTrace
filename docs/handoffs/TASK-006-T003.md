# Handoff TASK-006-T003

## Resumen

Se creó la frontera inmutable del refinamiento temporal: estados cerrados,
procedencia del timestamp, resumen de contadores, candidatos y el puerto
inyectable que usará la API. El paquete no inicializa red, Supabase, adapters ni
el índice al importarse.

## Requisitos implementados

- FR-009: `RefinementOutcome` solo expone la vista resultante; no conoce ni
  permite escribir el `VectorStore`.
- NFR-001: los tipos son independientes del segundo pase y permiten conservar
  el resultado base cuando el refinamiento no está disponible.

## Archivos modificados

- `services/api/xtrace_api/refinement/__init__.py`
- `services/api/xtrace_api/refinement/models.py`
- `services/api/xtrace_api/refinement/ports.py`

## Decisiones

- Los estados REST se representan con `StrEnum` para impedir valores fuera del
  contrato (`completed`, `disabled`, `unavailable`, `limited`, `failed` y los
  estados por candidato).
- `TimestampProvenance` mantiene origen, fuente, tipo de asset, URL saneada y
  posición; no contiene bytes.
- Todos los value objects son `dataclass(frozen=True)` y el puerto solo define
  `refine(...)` asíncrono.

## Tests y comandos

## Limitaciones y riesgos

- `RefinementPolicy` se importa solo bajo `TYPE_CHECKING`; su implementación y
  validación de límites pertenece a TASK-006-T004/T005.

## Revisión solicitada

Comprobar que los objetos son realmente inmutables, que los estados coinciden
con la spec y que el puerto no abre una vía de escritura del índice.
