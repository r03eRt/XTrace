# Handoff — PR-034

- **Proveedor y modelo usados** (obligatorio para auditar coste — p. ej. `provider: deepseek-official · model: deepseek-v4-flash`): `provider: deepseek-official · model: deepseek-v4-flash`
- **Resumen**: Fix del hallazgo de la validación del quickstart (PR-033): con el
  cableado REAL (CLI + worker + repos + `SafeHTTPClient`), los jobs `INDEX_VIDEO`
  del mock degradaban TODOS sus assets (`http://mock.local/...` bloqueado por el
  cliente HTTP real: allowlist/esquema) → 0 vídeos indexados y jobs failed. El
  mock ahora sirve sus assets **in-process, sin red**: el contrato `SourceAdapter`
  gana el método **opcional** `fetch_asset_bytes(url) -> bytes | None`
  (semántica: `None` = descargar por HTTP) y el pipeline lo **prefiere** frente a
  `AssetFetcher`/`SafeHTTPClient`. Validado end-to-end con el CLI real:
  `backfill --source mock --limit 5` + `run-worker --once` → 110 jobs, 110
  `done`, 0 errores, **50/50 vídeos `indexed`** (hallazgo: 45 failed, 0 indexados).
- **Requisitos implementados**: FR-003 / SC-001 (mock adapter ejecuta el flujo
  completo **sin red**, determinista), FR-011 / SC-002 (assets → frames →
  embeddings consultables), FR-005 (jerarquía de assets; el preview degrada sin
  tumbar el vídeo), FR-015 (sin artefactos temporales en la ruta in-process),
  contracts §1 (método opcional, sin cambios de contrato funcional para fuentes
  reales — xvideos sigue descargando por HTTP).
- **Archivos modificados** (solo `allowed_paths` del contrato):
  - `services/crawler/xtrace_crawler/adapters/base.py` — contrato documentado del
    método opcional `fetch_asset_bytes` en el protocolo `SourceAdapter`.
  - `services/crawler/xtrace_crawler/adapters/mock.py` — `fetch_asset_bytes` +
    generadores de imágenes Pillow sintéticas deterministas
    (`synthetic_sprite`/`synthetic_thumbnail`/`synthetic_asset_bytes`).
  - `services/crawler/xtrace_crawler/pipeline.py` — `_collect_frames` prefiere
    `adapter.fetch_asset_bytes` (ruta in-process: `BytesIO` para imágenes,
    temporal FFmpeg para previews) y cae a `AssetFetcher`/`SafeHTTPClient` con
    `None`; el cliente HTTP solo se construye si algún asset necesita la red.
  - `services/crawler/tests/unit/test_mock_adapter.py` — tests unit de
    `fetch_asset_bytes` (bytes estables entre llamadas/instancias, JPEG válidos,
    unicidad por vídeo, `None` para preview/URLs ajenas, adapter sin el método).
  - `services/crawler/tests/integration/test_pipeline.py` — regresión del
    hallazgo con el cableado REAL sin fakes de fetch; fallback HTTP para
    adapters sin el método; previews in-process con FFmpeg.
  - `docs/handoffs/PR-034.md` — este handoff.
- **Decisiones tomadas**:
  1. **Método opcional sin declararlo como miembro del cuerpo del protocolo**:
     verificado empíricamente (mypy strict + Python 3.11) que declarar
     `fetch_asset_bytes` en el cuerpo de `SourceAdapter` (como atributo con
     default o como método con body) lo convierte en miembro **obligatorio**:
     rompe la conformidad estructural de adapters que no lo implementan
     (xvideos, `_FakeAdapter` de test_adapters_base.py) en mypy Y en
     `isinstance` (runtime_checkable). El contrato se documenta en la docstring
     del protocolo y el pipeline lo descubre con
     `getattr(adapter, "fetch_asset_bytes", None)` (patrón estándar de
     extensiones opcionales); `None` = descarga HTTP, idéntica semántica al
     contrato pedido.
  2. **El mock fabrica solo imágenes (storyboard/thumbnail)**: `preview.mp4` →
     `None` → ruta HTTP (que sin transporte falla → degrada con warning; nunca
     abre sockets porque `SafeHTTPClient` rechaza el esquema antes de la red).
     El mock no genera mp4 sin ffmpeg (SC-001/SC-002 se cumplen con
     storyboard+thumbnails).
  3. **Paridad byte a byte con los tests existentes**: los generadores del mock
     replican exactamente las imágenes que `test_pipeline.py` ya servía vía
     `httpx.MockTransport` (sprite 2×2 de 48×27 + sello `zlib.crc32`); el
     router de tests ahora usa `synthetic_asset_bytes` como fuente única → la
     búsqueda SC-002 consulta exactamente lo que el pipeline indexa.
  4. **`fetch_asset_bytes` NO pasa por el rate limiter** (in-process, sin red;
    FR-009 aplica a llamadas a la fuente). `test_backfill_respects_rate_limiter`
    (11 requests exactos) sigue verde.
  5. **Cliente HTTP perezoso**: `_fetcher_for` solo se construye si algún asset
    necesita la ruta HTTP → con el mock real el pipeline crea 0 clientes (0
    superficie de red).
- **Tests añadidos**:
  - Unit (`test_mock_adapter.py`, 7): bytes estables entre llamadas e
    instancias; JPEGs válidos con dimensiones esperadas; unicidad por vídeo;
    `None` para preview/URLs ajenas/malformadas; `synthetic_asset_bytes` como
    fuente única; adapter sin el método → `getattr(...) is None`.
  - Integration (`test_pipeline.py`, 3):
    - `test_real_wiring_mock_indexes_videos_without_network` — **regresión del
      hallazgo**: worker + `JobsRepo` + `CrawlerRepo` + pipeline + `MockAdapter`
      SIN `client` inyectado ni transporte fake → 8 jobs todos `done`, 3/3
      vídeos `indexed`, frames deterministas (3 y 9), embeddings consultables
      por `ann_search`, sin temporales.
    - `test_adapter_without_fetch_asset_bytes_uses_http_path` — sin el método →
      `None` → ruta HTTP real (MockTransport) indexa igual (contrato de fuentes
      reales intacto).
    - `test_in_process_preview_bytes_are_extracted` — previews in-process
      (mp4 → temporal → FFmpeg); sin ffmpeg degradan y el vídeo sigue indexado.
- **Comandos ejecutados** (worktree `worktrees/PR-034`, `UV_CACHE_DIR=/tmp/uv-cache-xtrace`):
  - `uv run ruff check .` → All checks passed.
  - `uv run ruff format --check .` → 49 files already formatted.
  - `uv run mypy xtrace_crawler` → Success: no issues found in 23 source files.
  - `uv run pytest` → **279 passed, 1 failed** (ver Limitaciones).
  - Validación real del hallazgo (Supabase local, tabla `sources` con el
    manifest del `MockAdapter`, `enabled=false` — el mock está exento del gate
    SEC-002): `uv run xtrace-crawler backfill --source mock --limit 5` →

    `uv run xtrace-crawler stats --json` → `jobs_by_status: {"done": 110}`,
    `recent_errors: []`, `videos_by_status: {"indexed": 50}`.
- **Resultados**: el flujo offline real indexa el 100 % de los vídeos del mock
  (0 fallos `INDEX_VIDEO`; criterio Done de tasks.md PR-034 cumplido). Los
  warnings de degradación quedan solo para `preview.mp4` (esperado y contenido:
  el esquema http se rechaza antes de abrir socket — NFR-003). Baseline previo
  al cambio: 270 passed (verificado antes de implementar).
- **Limitaciones**:
  - **`tests/unit/test_cli.py::test_run_worker_once_builds_pipeline_and_dispatches_discover`
    queda ROJO (1 failed) y está FUERA de `allowed_paths` de PR-034**: el test
    codifica el comportamiento PRE-fix del hallazgo —"sin client inyectado los
    assets http degradan → 0 frames → transitorio con backoff" y
    `assert all(record.status in ("discovered", "indexing") ...)`. Con el fix,
    el cableado real indexa (vídeos `indexed`), que es exactamente el objetivo.
    **Cambio requerido (mínimo, en manos del orquestador/revisor)**: sustituir
    ese aserto por `assert all(record.status == "indexed" for record in repo.videos.values())`
    (y actualizar el comentario del test). Adicionalmente, ese test usa el
    `PgVectorStore` por defecto (sin fake): tras el fix escribe frames en la BD
    local; conviene inyectar un store fake (mismo archivo, fuera de mi alcance).
  - `contracts/README.md` §1 (fuera de `allowed_paths`) no documenta el método
    opcional; el contrato vive en la docstring de `adapters/base.py`. El
    orquestador puede sincronizarlo.
  - Los bytes in-process se generan con Pillow en cada llamada (CPU trivial);
    no hay caché (determinismo puro, NFR-003).
- **Riesgos**: bajo. La ruta HTTP de fuentes reales (xvideos) no cambia su
  firma ni su comportamiento: solo se consulta `fetch_asset_bytes` vía
  `getattr` y `None` cae a la ruta anterior. El único cambio de comportamiento
  es el esperado por el hallazgo (el mock indexa sin red). Riesgo menor: un
  adapter futuro que implemente `fetch_asset_bytes` debe respetar la semántica
  `None` = HTTP (documentada en el protocolo).
- **Trabajo pendiente**: sincronizar `contracts/README.md` §1 (decisión del
  orquestador); revisión independiente (`task-review`).
