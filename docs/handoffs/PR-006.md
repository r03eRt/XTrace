# Handoff — PR-006

- **Resumen**: Migración de base de datos Supabase para el Visual Search Spike:
  extensión `pgvector`, tablas `videos` / `frames` / `searches` con constraints
  únicos (idempotencia), índices HNSW sobre `embedding vector(768)`
  (`vector_cosine_ops`), índice sobre `phash` y sobre `video_id`, y RLS
  deny-by-default en las 3 tablas. Tests pgTAP en verde. Dimensión del embedding
  **D = 768** (fijada por PR-005, SigLIP2).

- **Requisitos implementados**:
  - FR-006 — índice consultable por similitud vectorial ANN: HNSW
    `idx_frames_embedding_hnsw` sobre `frames.embedding vector(768)` con
    `vector_cosine_ops` (ADR-0004).
  - FR-007 — tabla `videos` con estado (`discovered`/`pending`/`indexing`/
    `indexed`/`failed`, CHECK constraint) y `idx_videos_status`.
  - FR-008 — idempotencia: `UNIQUE(local_ref)` en `videos`;
    `UNIQUE(video_id, frame_seq)` y `UNIQUE(video_id, timestamp_ms)` en `frames`
    (NULLS DISTINCT por defecto en PG15 ⇒ múltiples frames sin timestamp son
    válidos; reindexar no duplica). Verificado con pgTAP (23505 en duplicados).
  - FR-018 — `searches` guarda solo metadatos (tipo, latencia, nº resultados);
    nunca la media de consulta (ADR-0006). `videos`/`frames` sin blobs de media.
  - SC-005 — constraint de unicidad probado (idempotencia a nivel de esquema).
  - SEC/data-model — RLS habilitada en `videos`, `frames`, `searches` con
    **deny-by-default**: sin políticas y sin privilegios para `anon`/
    `authenticated` (revoke explícito). El servicio Python accederá con
    `service_role` (servidor); nunca desde cliente.

- **Archivos modificados**:
  - `supabase/migrations/20260815000000_visual_search_spike.sql` (nuevo)
  - `supabase/tests/visual_search_spike_schema.test.sql` (nuevo)
  - `docs/handoffs/PR-006.md` (este archivo)

- **Decisiones tomadas**:
  - Extensión creada con `create extension if not exists vector;` (ADR-0004,
    idempotente). Versión instalada localmente: **pgvector 0.8.0**.
  - PKs `uuid` con `gen_random_uuid()`; se asegura `pgcrypto` por
    consistencia con la migración base (core PG13+ ya lo trae).
  - `phash` como `bigint` (tipo principal del data-model.md; el adaptador
    Python convierte el uint64 de imagehash a int64 con signo en PR-007).
  - `status`, `source_kind` y `search_type` como `text` + CHECK
    constraint (evita migraciones de enum nativo; valida a nivel DB).
  - `UNIQUE(video_id, timestamp_ms)` global (NULLS DISTINCT), como en el
    data-model.md — no requiere índice parcial.
  - Trigger `trg_videos_set_updated_at` + función `public.set_updated_at()`
    para `updated_at` (data-model.md).
  - RLS deny-by-default estricto: sin grants y sin políticas (ni siquiera de
    lectura) para `anon`/`authenticated`; revoke explícito como defensa en
    profundidad y documentación de intención.
  - Timestamp de migración: `20260815000000` (posterior a
    `20260805171159_init_health_check.sql`), sugerido por el orquestador.

- **Tests añadidos**: `supabase/tests/visual_search_spike_schema.test.sql`
  (pgTAP, 32 asserts): extensiones; existencia de tablas; dimensión
  `vector(768)`; uniques (local_ref, video_id+frame_seq, video_id+timestamp_ms);
  FK ON DELETE CASCADE; índices (status, phash, video_id, HNSW); método de acceso
  `hnsw` y opclass `vector_cosine_ops`; RLS activa en las 3 tablas; ausencia
  de políticas; anon/authenticated sin privilegio; throws 42501 (lectura anon);
  trigger updated_at; flujo funcional service_role (inserts válidos);
  negativos 23505 (duplicados) y 23514 (checks). Trazabilidad FR/SC en cada
  descripción de assert.

- **Limitaciones**:
  - pgTAP vía `supabase test db` (CLI local); no se ejecutó en CI cloud.
  - `has_unique` de pgTAP no matchea en esta versión del contenedor; los
    uniques se verifican vía `pg_constraint` (equivalente y más explícito).
  - Parámetros HNSW por defecto de pgvector; tuning con benchmark
    (SC-001/SC-003) queda para PR-016/017.
  - `halfvec(768)` evaluado por ADR-0004: se usa `vector(768)` en el spike;
    migración a halfvec sería una migración de columna posterior si el benchmark
    lo justifica.

- **Riesgos**:
  - El acceso de cliente queda bloqueado por diseño (sin grants + RLS), pero
    cualquier futuro requisito de lectura pública requerirá política + grants
    explícitos (cambio de seguridad revisado).
  - `chk_searches_search_type` solo admite `image` (spike); la búsqueda por
    clip (D1) exigirá ampliar el CHECK en la feature siguiente.
