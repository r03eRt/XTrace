# Handoff PR-068 · Integración end-to-end con fixtures (pipeline + Supabase local) + quickstart

**Feature**: `specs/008-redgifs-adapter` · **Depende de**: PR-067 `DONE`.

## Resumen

Suite de integración determinista (fixtures + `httpx.MockTransport`, sin red
real) que ejercita el flujo completo del adapter `redgifs` contra el pipeline
y Supabase local: DISCOVER → FETCH_METADATA → INDEX_VIDEO, frames sin
timestamp (thumbnail+poster), INCREMENTAL sin duplicados, y aislamiento ante
un fallo persistente. Añadidos `quickstart.md` del operador y una sección
`redgifs` en el README del servicio. Esta suite corrió **después** de la
validación real de PR-069, así que reproduce en CI lo mismo que ya se
demostró con la API real.

## Requisitos implementados

FR-009, DATA-002, DATA-003, NFR-001, NFR-002, SC-001 (offline), SC-003, SC-007,
US3 (aislamiento).

## Archivos modificados/creados

## Decisiones

- El `client` inyectado en `_build()`/`CrawlerPipeline` fija su propia
  allowlist de assets (`media.redgifs.invalid`, dominio reservado — SEC-004):
  como el pipeline usa el cliente inyectado tal cual cuando se le pasa uno
  (no construye el suyo a partir de `adapter.asset_hosts` en ese caso), el
  test nunca necesita mencionar el host real `media.redgifs.com` del
  adapter — mantiene el mismo estándar de fixtures/tests-sin-dominios-reales
  que el resto de la suite.
- El caso de aislamiento (US3) usa `CrawlerPipeline` directamente (sin
  `_build()`) con un `adapter_for` que enruta por `job.payload["source"]`
  entre un `RedgifsAdapter` roto (401 persistente) y un `MockAdapter` normal,
  para demostrar que un job de una fuente no bloquea los de otra en la misma
  pasada del worker.
- `def-homemade-two` (fixture sin `poster`) produce deliberadamente solo 1
  frame: cubre la degradación de `get_visual_assets` sin fallar (FR-005).

## Comandos ejecutados

```bash
cd services/crawler
uv run ruff check . && uv run ruff format --check .    # All checks passed!
uv run mypy tests/integration/test_pipeline.py
  # 10 errores preexistentes (idénticos a antes de este PR); 0 nuevos.

# Suite destructiva (con consentimiento explícito del humano — truncaba el
# backfill real de PR-069 en la Supabase local; decisión: ejecutar y
# rehacer el backfill real después si se necesita):
XTRACE_CRAWLER_ALLOW_DB_RESET=1 uv run pytest tests/integration/test_pipeline.py -k redgifs -q
  # 3 passed
XTRACE_CRAWLER_ALLOW_DB_RESET=1 uv run pytest tests/integration/test_pipeline.py -q
  # 30 passed (toda la suite de integración, no solo redgifs)

uv run pytest tests/unit -q   # sigue en verde tras la ejecución destructiva
supabase db reset             # BD local devuelta al estado limpio del seed
```

## Resultados

Los 3 tests nuevos y la suite completa de integración pasan. La ejecución
truncó y repobló `jobs`/`videos`/`sources` (comportamiento esperado y
aceptado explícitamente por el humano); al terminar se restauró el estado
limpio del seed con `supabase db reset` — **el backfill real de PR-069
(101 vídeos de `homemade`/`real-cellphone-clips`) ya no está en la BD local**;
se puede rehacer en cualquier momento con los comandos de
`quickstart.md § Backfill real acotado`.

## Limitaciones

- Esta suite es offline (fixtures); no reemplaza la validación real de
  PR-069, la complementa para que el flujo quede cubierto de forma
  determinista en CI sin depender de la API real ni del rate limit.
- El caso de aislamiento no prueba el mecanismo de renovación de token (401
  transitorio) — solo el caso de fallo persistente, que es lo que exige US3.
