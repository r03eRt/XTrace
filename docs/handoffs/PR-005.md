- **Resumen**: Proveedor **real** de embeddings visuales SigLIP v1 en local
  (xtrace_spike/embeddings/siglip_local.py): open_clip + torch en CPU
  (Intel-Mac, sin GPU en el spike), modelo **ViT-B-16-SigLIP** (pretrained
  webli), **D = 768**, imagen 224x224, sub-batches de 32 (FR-005) y filas
  L2-normalizadas (contracts §3). Import **lazy** de torch/open_clip dentro
  de _ensure_loaded, de modo que los gates BASE (ruff/mypy/pytest) pasan
  sin tener el extra siglip instalado. El test de integración @slow
  (10 tests, 246 líneas) valida contrato, D, shape/dtype/L2, batching,
  determinismo, recall exacto/variantes/negativas y throughput. Medido en
  la máquina real: **D = 768**, **~8-9 frames/s en CPU**, recall@1 por
  variante: resize 0.81, jpeg 0.75, crop 0.62, color 1.00.
- **Requisitos implementados**:
  - **FR-005**: SiglipLocalProvider.embed_images(images) -> np.ndarray (N, D)
    float32 L2-normalizado, procesando en sub-batches de batch_size (32).
  - **ADR-0005/0007 + contracts §3**: contrato EmbeddingProvider
    (model_id openclip-ViT-B-16-SigLIP-webli, dimension 768, embed_images).
    D queda fijada por el modelo (mapa _MODEL_DIMENSIONS, sin cargar pesos
    para conocerla; sonda forward solo para modelos fuera del mapa).
  - Trazabilidad: el test integra pytest.importorskip("torch") + marca
    @slow para que CI/base sigan verdes sin el extra; el módulo se salta
    (1 skipped) cuando torch no está instalado.

- **Decisiones tomadas**:
  - **SigLIP v1, ViT-B-16-SigLIP, pretrained webli, D = 768**, en CPU
    local (Intel-Mac, torch 2.2.2, sin GPU). Fijado por el mini-benchmark de
    PR-005 y anexado al ADR-0005; la usará el esquema DB (PR-006).
  - Import lazy de torch/open_clip (importlib en _ensure_loaded):
    gates BASE sin el extra instalado (diseño verificado en la Tarea 2).
  - El mapa _MODEL_DIMENSIONS evita cargar el modelo solo para conocer D
    (768 para todas las variantes ViT-B-16, 1024 para ViT-L-16); sonda
    forward solo para modelos desconocidos.
  - Corrección del fixture del test (hallazgo real): _make_images generaba
    solo **4 imágenes únicas** (recreaba el rng por imagen y los tipos
    gradiente/tablero no consumían rng) — el índice de 16 "frames" era 4
    imágenes repetidas 4x, lo que rompía recall@1 de duplicados (colapsan al
    primer match) y hacía que "negativas" fueran píxel-idénticas a frames del
    índice (similitud 1.0). Corregido con un único rng secuencial por llamada
    y variedad por imagen (desplazamiento/ganancia en gradientes, bloque/
    colores en tableros). Tras el fix: 10/10 tests verdes.
  - Workaround para medir (hallazgo ambiental, NO corregible aquí): torch
    2.2.2 (compilado contra el C-API de numpy 1.x) es incompatible con
    numpy 2.4.6 del entorno base — RuntimeError: Numpy is not available
    (Failed to initialize NumPy: _ARRAY_API not found). Para la medición
    se instaló numpy 1.26.4 a nivel de venv (sin tocar el repo) y se ejecutó
    con uv run --no-sync. Ver Riesgos/Recomendación.

- **Limitaciones**:
  - numpy 2.4.6 (entorno base, pyproject) + torch 2.2.2 (extra siglip) es una
    combinación **rota en runtime** (torch 2.2.x compilado contra numpy 1.x).
    El comando canónico de la tarea 1 (uv sync --extra siglip + pytest
    directo) falla tal cual está commiteado; la medición requirió numpy
    1.26.4 a nivel de venv + --no-sync.
  - Aviso PytestUnknownMarkWarning por la marca slow no registrada en
    pyproject.toml ([tool.pytest.ini_options] no define markers). No es error;
    no se tocó pyproject (fuera de allowed_paths).
  - Throughput medido sobre imágenes sintéticas pequeñas: sanity, no
    benchmark formal (PR-016). CPU single-thread: ~8-9 frames/s es el coste
    real del spike en esta máquina.
  - El fixture sintético puede generar casi-duplicados entre "negativas" y el
    índice (margen fino 0.9965 vs 1.0); aceptado para smoke.
