# Handoff — PR-045

- **Proveedor y modelo usados** (obligatorio para auditar coste): `provider: deepseek-official · model: deepseek-v4-flash`
- **Resumen**: La 3a validación real (2026-08-16) confirmó que el discover parsea
  los 48 ids de la home, **pero** la página de vídeo reconstruida como
  `https://www.xvideos.com/video.<id>/` (SIN slug) devuelve **404 en todos**: el
  href real del listado es `/video.<id>/<num>/<num>/<slug-titulo>` y es la ÚNICA
  URL que la fuente acepta. PR-045 enmienda el contrato (§1): `DiscoverPage`
  gana `page_urls: dict[str, str] = {}` (opcional, external_id → href completo
  del listado) y `get_video(external_id, *, page_url=None)` (kwarg opcional).
  `discover()` de xvideos rellena `page_urls` con el href íntegro; `get_video`
  lo resuelve contra el host canónico cuando viene (fallback `/video.<id>/`
  si no, y nunca usa hrefs ajenos al host — SEC-001); el pipeline reenvía
  `page.page_urls.get(external_id)` durante DISCOVER (FETCH_METADATA sigue sin
  él, `None`); el `MockAdapter` acepta el kwarg y lo ignora. Retrocompatible:
  `page_urls` vacío por defecto y `page_url=None` → mismo comportamiento previo.
- **Requisitos implementados**: FR-004 (discover → get_video con la URL canónica
  real de xvideos, hallazgo de la 3a validación), FR-001 (contrato ampliado:
  `DiscoverPage.page_urls` opcional + firma `get_video(page_url=...)`),
  SEC-001 (el `page_url` solo se usa si es path relativo o http(s) del host
  canónico; el SafeHTTPClient con allowlist queda como segunda barrera),
  SEC-004 (fixtures/HTML sintéticos, `xvideos.invalid`, nada real en el repo),
  constitución §3 (trazabilidad PR-045 en docstrings, contracts §1 y tests).

- **Decisiones tomadas**:
  1. **`page_url` SÍ se declara en el cuerpo del Protocol** (a diferencia de
     `fetch_asset_bytes`/`asset_hosts`): es un kwarg opcional con default; mypy
     exige que las implementaciones lo acepten (verificado con probe), así que
     xvideos y mock se actualizan. Los fakes de tests fuera de allowed_paths no
     se tipan (el gate es `mypy xtrace_crawler`, no tests) y nunca reciben el
     kwarg en runtime.
  2. **El href se guarda verbatim** en `page_urls` (primer href por vídeo, mismo
     dedup que los IDs) y se resuelve solo contra el host canónico al usarlo:
     sin normalización especulativa, sin tocar `parse_video_page` (sigue
     tomando el ID de `og:url`/`page_url` de la respuesta).
  3. **El pipeline pasa `page_url` solo durante DISCOVER** (donde existe el
     href); FETCH_METADATA/CHECK_AVAILABILITY/INDEX_VIDEO no cambian (`None` →
     fallback, retrocompatible).
  4. **Rama anti-bucle conserva `page_urls`**: la página devuelta en el caso
     "0 IDs nuevos" mantiene los hrefs (mismo contrato para el llamador).
