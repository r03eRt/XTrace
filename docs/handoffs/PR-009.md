- **Resumen**: Deduplicación de frames representativos por pHash (FR-003).
  `ingest/dedupe.py` expone `dedupe_frames(frames, *, threshold=10)`:
  recorre los frames extraídos por PR-008 en orden temporal, calcula el
  pHash de cada uno con `hashing.phash.compute_phash` (PR-004, sin nuevas
  dependencias) y conserva el frame solo si su distancia de Hamming a
  **todos** los representativos ya conservados supera el umbral (greedy
  determinista). Invariante: ningún par del resultado es near-duplicate.
  El representativo de cada grupo es el primero en el tiempo; un vídeo
  entero casi idéntico colapsa a 1 frame (edge case de la spec). El
  umbral por defecto (10) sigue la guía de ADR-0005 (near-exact <= 10
  bits).
- **Requisitos implementados**:
  - **FR-003**: `dedupe_frames` reduce frames casi idénticos (distancia
    de Hamming <= threshold) conservando un subconjunto representativo
    ordenado y determinista; umbral configurable en [0, PHASH_BITS]
    (0 = solo duplicados exactos; PHASH_BITS = colapso agresivo a 1
    frame). Reutiliza `compute_phash` + `hamming_distance` de PR-004.
  - Trazabilidad con la spec: edge cases cubiertos (vídeo casi idéntico
    -> pocos frames; vídeo sin frames distinguibles), errores controlados
    bajo `IngestError` para que el pipeline (PR-010) marque failed sin
    abortar (FR-001 US1 esc. 3) y determinismo (SC-007 mindset).

- **Decisiones tomadas**:
  - Algoritmo greedy comparando contra **todos** los representativos
    conservados (no solo el último): conserva más variedad en transiciones
    lentas (zoom/pan) y da una garantía fuerte (ningún par del output es
    near-duplicate). Coste O(N x K) con K <= N (frames/vídeo tip. 30).
  - El representativo de cada grupo es el primero en el tiempo:
    determinista, preserva el orden de extracción (cronológico) y da
    timestamps estables para el resto del pipeline (FR-008/FR-012).
  - Umbral por defecto 10 bits (guía ADR-0005: near-exact <= 10).
  - El pHash se calcula dentro del dedupe leyendo el PNG del frame desde
    disco (los frames de PR-008 son PNG sin pérdida; ADR-0005). No se
    añade ninguna dependencia nueva.
  - Errores controlados: frame ilegible (fichero desaparecido o corrupto)
    -> `DedupeError` (subclase de `IngestError`); configuración inválida
    (threshold fuera de rango) -> `ValueError` antes de leer imágenes.
  - Tests sin FFmpeg: se construyen `ExtractedFrame` directamente con
    imágenes sintéticas deterministas (PIL + numpy, misma familia que
    test_phash) guardadas como PNG en tmp_path; el límite del umbral se
    prueba contra la distancia real medida con la API pública de PR-004
    (variante crop 1-4% / brillo, distancia 1-10; semillas distintas,
    distancia >= 26).

- **Limitaciones**:
  - El dedupe compara contra todos los representativos: O(N x K); trivial
    para frames/vídeo típicos (~30) del spike, pero a vigilar si N crece
    mucho (fuera del alcance del spike, spec: sin escalado).
  - El pHash se calcula leyendo el PNG del frame; el coste es el de
    compute_phash por frame conservado en el peor caso (cada frame se lee
    una vez; el hash se calcula siempre, el frame se descarta o conserva).
  - Dedupe por pares vs el primero del grupo: en secuencias con cambios
    graduales extremos (zoom lento), el representativo del grupo es el
    primero; aceptado para el spike (alternativa de centroides = coste y
    complejidad sin justificar).
- **Riesgos**:
  - El umbral por defecto (10) es orientativo (ADR-0005): el benchmark
    (PR-016/017) podrá calibrarlo vía CLI (PR-011 expondrá
    --dedupe-threshold según plan.md).
  - Imágenes sintéticas de los tests: distancias medidas en runtime con la
    API de PR-004 (precondiciones con semillas fijas); si una versión de
    imagehash cambiara el pHash, los tests fallarían alto indicando el
    cambio (no se silencian).
