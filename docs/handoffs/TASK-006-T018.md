# Handoff TASK-006-T018

## Resumen

Se completó la degradación controlada del refinamiento: el límite global y el
límite por candidato cubren resolución de catálogo, adquisición/materialización
y evaluación de embeddings. Los resultados agotados conservan el primer pase y
marcan `limited`; los errores de fuente/asset marcan `unavailable` sin
interpolación.

El bridge exige que el adapter haya pasado previamente el registry y el gate de
`sources.enabled`, respeta el `RateLimitSpec`, valida allowlist y activa la
validación anti-DNS-rebinding del cliente HTTP. La URL de evidencia se sanitiza
antes de entrar en provenance (sin credenciales, query ni fragmento). Los
clientes de adapters se cierran en el mismo ciclo async de la petición, incluso
con la política desactivada.

## Decisiones y límites

- La evaluación síncrona se ejecuta en un worker bajo `wait_for`; el evaluator
  mantiene la propiedad de cerrar las imágenes aunque el request agote su
  presupuesto.
- El bridge no descarga assets si no hay allowlist, y nunca deriva hosts de la
  URL recibida.
- El cierre de clientes absorbe errores de cleanup para no convertir un fallback
  válido en error de API.
