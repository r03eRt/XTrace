  **Sin cambios en el core** (solo los `allowed_paths` del contrato).

- **Decisiones tomadas** (reflejo de D1–D5 de la spec 007 / ADR-0015 / A1):
  - D1: host canónico `xhamster.com`; allowlist de página `{xhamster.com,
    www.xhamster.com, es.xhamster.com}` (A1: `es.*` como objetivo de
    redirect/URL canónica, no como base).
  - D2: `discover` exige `section` (fail-fast `ValueError` si falta o no empieza
    por `/`), también con cursor (el pipeline reenvía `section` en cada página,
    PR-049). Cursor = path del `a.page-button-link` siguiente al activo;
    anti-bucle: candidato == path actual → `None`, 0 IDs nuevos → `None`.
  - D3/SC-004: `preview_url=None` siempre; `get_visual_assets` emite UN
    `storyboard` (URL de `storyboard_urls[0]`, position/timestamp None) + UN
    `thumbnail`; sin sprite → solo thumbnail; sin ambos → `[]`.
  - D5: manifest `robots_reviewed=true`, `terms_reviewed=true`,
    `review_date="2026-08-19"`, `rate_limit=RateLimitSpec(2000, 0.5)`; el gate
    efectivo (`sources.enabled=true` en BD) se prueba en PR-063.
  - FR-006: `asset_hosts` PROVISIONAL (fail-closed): `thumb-v0..v9.xhcdn.com`
    + `ic-vt-nss.xhcdn.com` — validar/ampliar en PR-065.
  - **Hallazgo de implementación (documentado)**: en la captura real el
    `spriteLoader.template` vive anidado en
    `window.initials.xplayerPluginSettings.spriteLoader.template` (y se refleja
    en `videoModel.spriteURL`); `_sprite_template()` acepta la forma canónica de
    la spec (`spriteLoader.template` top-level, la de los fixtures) y ambas
    como fallback — siempre desde `window.initials`, nunca desde `data-sprite`.
  - Selector de ítem SIN `[href^="/videos/"]` a propósito: el href real del
    listado es absoluto (`https://es.xhamster.com/videos/...`); el filtro es el
    patrón del path `/videos/<slug>-<id>`.
