# Handoff — PR-029

- **Proveedor y modelo usados** (obligatorio para auditar coste): `provider: deepseek-official · model: deepseek-v4-flash`
- **Resumen**: Descarga y transformación de visual assets (nunca vídeo completo) en
  `xtrace_crawler/assets/`: `fetch.py` (descarga de assets permitidos vía
  `SafeHTTPClient` de PR-024 a directorio temporal dedicado, con `max_bytes` y cleanup
  `try/finally` garantizado incluso si el llamador falla), `storyboard.py` (recorte de
  tiles de un sprite con Pillow: `cols`×`rows` + tamaño de tile; timestamp aproximado
  `round(position/total*duration_ms)` cuando la fuente da duración; determinista y sin
  red), `preview.py` (FFmpeg extrae frames de previews CORTOS con intervalo
  configurable; **rehúsa** cualquier input que parezca vídeo completo: duración >
  límite configurable default **120 s** → `PreviewTooLongError`, o duración no
  verificable → `PreviewExtractionError`). SC-006 se cumple por construcción: el tipo
  `AssetKind` del contrato (PR-020) solo admite storyboard/thumbnail/preview, y el
  fetcher solo acepta `VisualAsset`.
- **Requisitos implementados**: FR-005 (obtener visual assets por jerarquía, MUST NOT
  descargar vídeos completos) · FR-015 (limpieza de todos los artefactos temporales
  incluso cuando un job/llamador falla: `try/finally` en `AssetFetcher.fetch`) ·
  SC-006 (0 descargas/procesos de vídeo completo: rechazo por duración y por duración
  desconocida con errores tipados) · contracts §7 (media descargada solo temporal, dir
  gitignored del sistema, cleanup `try/finally`; nunca vídeo completo) · NFR-003
  (tests 100 % sin red: sprite sintético con Pillow + `httpx.MockTransport`; previews
  sintéticos con lavfi).
- **Archivos modificados** (todos dentro de `allowed_paths`):
  - `services/crawler/xtrace_crawler/assets/__init__.py` (nuevo, paquete del contrato)

- **Decisiones tomadas**:
  1. **Pillow sin tocar `pyproject.toml`** (no está en mis `allowed_paths`): se consume
     **transitivamente** vía la dependencia editable `xtrace-spike` (declara
     `pillow>=12.3.0`; verificado en `uv.lock` y en el venv instalado). Riesgo
     documentado abajo; PR-030/032 pueden declararlo explícito si el orquestador lo
     autoriza.
  2. **`AssetFetcher.fetch` como async context manager** que gestiona su propio
     directorio temporal (`tempfile.mkdtemp(prefix="xtrace-crawler-asset-")`) y lo
     elimina en `finally` (éxito, error de descarga O error del llamador). No reutilicé
     `SafeHTTPClient.download_to_temp` (PR-024) porque gestiona su propio dir y deja el
     cleanup al llamador; aquí el cleanup es del fetcher (FR-015) y añade sufijo por
     tipo de asset (`.jpg`/`.mp4`).
  3. **`max_bytes` aplicado vía `SafeHTTPClient.get_bytes`** (streaming + límite exacto,
     `DownloadTooLargeError` si se supera), default **10 MiB por asset** configurable en
     el constructor del fetcher. Errores de descarga se propagan tipados sin dejar
     temporales (errores contenidos, contracts §7).
  4. **`split_storyboard` puro y estricto**: `tile_size` opcional (se deriva del sprite
     si es divisible por el grid); con `tile_size` explícito se recorta la región
     superior-izquierda (tolera padding) pero se rechaza un sprite más pequeño que el
     grid. Timestamp `None` si no hay duración (paridad FR-012 spike: sin timestamp no
     falla).
  5. **`PreviewFrameExtractor`**: sondea duración con `ffprobe` ANTES de extraer;
     duración > `max_duration_s` (default 120.0 s, validado > 0) → `PreviewTooLongError`
     (SC-006); duración **no determinable** (archivo no multimedia, ffprobe ausente,
     timeout) → `PreviewExtractionError` (rehusar lo no verificable = política
     safety-first de SC-006). Extracción con filtro `fps=1/<interval_s>`; frames JPEG
     con `timestamp_ms` aproximado `round(index*interval_s*1000)` monotónico desde 0.
  6. **Fixtures 100 % sintéticos** (SEC-004): sprite generado con Pillow (color único
     por tile + borde blanco, sin RNG) y preview mp4 generado con `ffmpeg -f lavfi
     testsrc` (libx264, verificado disponible). Nada de media real en el repo. Si
     ffmpeg no está en PATH, los tests de preview se marcan `skip` con motivo
     documentado (contrato PR-029).
  7. `tests/fixtures/assets/__init__.py` creado (patrón Ola A; dentro de
     `allowed_paths` via `assets/**`); no toqué `tests/fixtures/__init__.py` (territorio
     de PR-021, archivos disjuntos).
- **Tests añadidos**: `tests/unit/test_assets.py` — 20 tests, todos referencian el
  requisito que validan (constitución §3): storyboard (FR-005) nº de tiles/tamaño/
  posición row-major · recorte exacto y tiles distinguibles (píxel central = color
  único, borde blanco) · timestamps aproximados `round(i/12*12000)` coherentes y
  crecientes · sin duración → `None` · determinismo (NFR-003, `get_flattened_data`) ·
  `tile_size` explícito con padding · geometría inválida rechazada (grids 0, tile 0,
  sprite menor que grid, no divisible, duración negativa); fetch (FR-005/FR-015)
  descarga a temporal con contenido exacto y sufijo por tipo · `max_bytes` y default
  (10 MiB) respetados sin temporales · error HTTP 404 contenido sin temporales ·
  cleanup `try/finally` si el llamador lanza; preview (FR-005/SC-006) frames a
  intervalo configurable (2 s → 2–3 frames, timestamps 0/1000/…, JPEGs decodificables
  con Pillow) · determinismo · rechazo por duración con límite configurable ·
  default 120 s · duración desconocida rehusada · intervalos ≤ 0 y `max_duration_s` ≤ 0
  rechazados.

- **Limitaciones**:
  - **Pillow consumido transitivamente** (no declarado en `pyproject.toml` del crawler
    porque no está en `allowed_paths`). Funciona hoy (ADR-0011: el spike es dependencia
    editable), pero si el spike dejara de declarar `pillow`, `assets/` se rompería.
    Recomendación: PR-030 o el orquestador pueden declarar `pillow>=12.3.0` explícito.
  - El filtro `fps` de ffmpeg puede descartar el frame final según versión: los tests
    aceptan el rango esperado (2–3 frames para 2 s a 1 frame/s) y verifican
    timestamps/coherencia, no un conteo rígido.
  - `preview.py` ejecuta `ffmpeg`/`ffprobe` síncronos (bloqueantes); el pipeline
    (PR-030) deberá llamarlos fuera del event loop o aceptar el bloqueo puntual
    (previews cortos, pocos frames).
  - La imposición real del intervalo/timestamps depende del decode de ffmpeg; los
    timestamps de preview son aproximados por diseño (igual estilo que storyboard).
- **Riesgos**: si el pipeline (PR-030) construyera URLs con otro cliente HTTP, se
  saltaría la política de PR-024 → debe pasar siempre por `SafeHTTPClient` +
  `AssetFetcher`. Un input corrupto con duración no verificable se rehúsa (SC-006) y
  el job quedará `failed` con el error tipado; el worker (PR-027) debe tratarlo como
  terminal o transitorio según política.
- **Trabajo pendiente**: PR-030 cableará `VisualAsset` → `AssetFetcher` →
  `split_storyboard`/`PreviewFrameExtractor` → frames con timestamp → pHash/embedding
  (spike). Nada pendiente en mis archivos.
