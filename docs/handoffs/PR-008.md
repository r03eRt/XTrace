- **Resumen**: Ingesta del spike de búsqueda visual. ingest/dataset.py
  recorre un dataset local de vídeos (FR-001) y produce DatasetVideo con un
  local_ref estable (ruta relativa POSIX al root, independiente del cwd).
  ingest/frames.py inspecciona cada vídeo con FFprobe (duración, dimensiones,
  fps, codec) y extrae N frames representativos con FFmpeg (muestreo temporal
  uniforme, escala y nº de frames configurables, PNG sin pérdida) en un
  directorio temporal único por vídeo, con cleanup garantizado en try/finally
  (FR-009 · ADR-0006). Los temporales quedan listados en
  ExtractionResult.temporary_paths para el cleanup del llamador (pipeline,
  PR-010). Errores controlados (fichero corrupto, sin stream de vídeo, fallo
  de FFmpeg) se propagan como subclases de IngestError para que el pipeline
  marque el vídeo como failed y continúe con el resto del dataset (FR-001,
  acceptance scenario 3 de US1).
- **Requisitos implementados**:
  - **FR-001** (dataset local): scan_dataset(root, allowed_extensions=...)
    recorre recursivamente (sin red), ignora ocultos, orden determinista,
    local_ref estable = ruta relativa POSIX al root (sin resolver symlinks,
    estable frente al cwd del proceso; testado con monkeypatch.chdir).
  - **FR-002** (frames representativos): probe_video() (FFprobe) +
    extract_frames() (FFmpeg): muestreo uniforme frames_per_video
    (configurable, default 30) y escala scale_width (configurable, default
    256, proporción preservada; None = sin escala). Timestamp por frame
    (ms, equidistante) para idempotencia posterior (UNIQUE(video_id,
    timestamp_ms), FR-008) y timestamp aproximado de búsqueda (FR-012).
  - **FR-009 / ADR-0006** (temporales seguros): el context manager
    extract_frames borra el directorio temporal en finally incluso si falla
    FFprobe/FFmpeg (SC-006 a nivel de módulo); temporary_paths lista los
    temporales para cleanup.

- **Decisiones tomadas**:
  - Muestreo: N frames por vídeo equidistantes en el tiempo (filtro
    fps=1/interval de FFmpeg sobre la duración medida por FFprobe, con
    -frames:v N para acotar exactamente a N y -fps_mode vfr para no duplicar).
    Frames en PNG sin pérdida (mejor fuente para pHash y embeddings;
    ADR-0005). Vídeos con menos frames únicos que N producen duplicados (el
    dedupe pHash de PR-009 los colapsa).
  - Timestamps: derivados analíticamente (i x duration/N, en ms) sobre la
    rejilla uniforme del filtro fps; estables entre ejecuciones (test de
    reproducibilidad incluido).
  - local_ref estable: ruta relativa POSIX al root del dataset, sin resolver
    symlinks; único por vídeo; no depende del cwd (testado).
  - Errores controlados: DatasetError, ProbeError y FramesExtractionError
    heredan de IngestError (definida en ingest/__init__.py — único lugar que
    encaja sin violar allowed_paths); configuración inválida → ValueError
    antes de tocar FFmpeg.
  - Fixtures sin binarios comprometidos: los tests generan el vídeo en
    tmp_path con FFmpeg (testsrc2 es determinista; la opción seed no existe
    en FFmpeg 7.1.1 y no es necesaria). Comando documentado en el docstring
    del helper y en este handoff:
    ffmpeg -v error -y -f lavfi -i "testsrc2=duration=2:size=320x240:rate=25"
    -c:v libx264 -pix_fmt yuv420p fixture.mp4
  - CI sin FFmpeg: los tests de probe/extracción hacen skip si ffmpeg/ffprobe
    no están en el PATH (los tests de scan_dataset no requieren FFmpeg y
    siempre corren). En ubuntu-latest de GitHub Actions FFmpeg está
    preinstalado.

- **Limitaciones**:
  - La extracción depende de ffmpeg/ffprobe en el PATH; sin ellos los tests
    de probe/extracción se saltan (no fallan). El CI de GitHub Actions
    (ubuntu-latest) incluye FFmpeg.
  - scale_width exige un único valor por extracción (sin multi-scale); el
    pipeline puede llamar varias veces si hace falta.
  - El conteo exacto de frames es N con inputs CFR; con inputs VFR exóticos
    -frames:v puede producir menos de N (el filtro fps emite lo que puede);
    el dedupe (PR-009) es el que garantiza representatividad final.
- **Riesgos**:
  - Timestamps derivados de la rejilla uniforme (no del PTS real de cada
    frame): desviación sub-ms frente al PTS real; irrelevante para
    pHash/embeddings y para el timestamp aproximado de búsqueda (FR-012).
  - PNG temporal más pesado que JPEG; irrelevante porque se borra tras
    indexar (ADR-0006) y es la fuente sin pérdida para pHash/embeddings.
  - Vídeos muy cortos (< N frames únicos) generan duplicados temporales que
    el dedupe de PR-009 colapsa (comportamiento esperado, edge case de la
    spec).
